# 旧全程流程 ↔ 新任务文件：逐段对照讲解

这份文档回答三个问题：

1. 你原来那份 `renwu.c` 里到底写了什么（**尤其是那些看不懂的编号**）；
2. 它被换算成新任务文件之后，每一段长什么样；
3. 转换时哪些东西变了、哪些没变、第一次上板要盯什么。

对照的两样东西：

| | 在哪 | 是什么 |
|---|---|---|
| 旧 | `Haixin/Hardware/renwu.c` 的 `void A()`（源文件 120~998 行） | 上一版能跑完全程的手写状态机；`renwu()` 里是个 `switch`，1→A、2→B、3→C、0→D，**全程比赛走的就是 A** |
| 新 | `tools/console/web/src/lib/tasks/renwu-lap.json` | 上位机「任务」页点「导入」得到的状态机：**15 个状态 / 208 块 / 镜像 2434 字节**（2026-10-07 第二版；第一版 15/190/**2127 B** 的原件留在同目录 `renwu-lap.json.bak`） |
| 抽词 | `out/_renwu_segments.txt` | 旧代码按 `black_num` 切段后的有效语句清单（写这份文档时的底稿，带旧文件行号） |
| 生成 | `out/_gen_lap.py` | 一次性转换脚本：把上表逐段核对过的语句写成 DSL，生成上面的 JSON |

> 上位机里现在每块、每个字段下面都有一行白话说明，鼠标停在下拉/字段/块上还有完整的提示框——看不懂哪个块，先看那行小字。

- **`TurnLeftFixed()` / `TurnRightFixed()` 两块板都是名字反的**：`TurnRightFixed()` 的函数体调的是 `TurnLeft()`

## 0. 先记住四件事，不然旧代码永远看不懂

### ① `black_num` 不是"黑线数量"，是"我走到第几段了"

旧代码里每段长这样：

```c
if (tracing_data[0]==0 && ... && tracing_data[7]==0 && black_num==4) {
    ...做一串动作...
    black_num = 6;          // 下一段的段号
}
```

`black_num` 是个**段号计数器**（名字起坏了，看着像"黑线数"）。所以新任务里「状态 4」= 旧代码 `black_num==4` 那一段，一一对应。

段号不是连着的：`0→1→2→3→4→6→7→9→10→11→13→17→18→19→21→23→24→25→26→27→28`，跳过的段号在旧代码里根本进不去（见 §2 末尾）。

### ② 每段的入口条件都是"八个探头全白"

`Haixin/Hardware/tracing.c:9-16` 写的是：

```c
tracing_data[i] = !HAL_GPIO_ReadPin(...);   // 取反
```

⇒ **`tracing_data[i] == 1` 才是"这个探头看见黑线"**，所以 `tracing_data[0..7] == 0` 是**八个探头一个都没看见黑线** = 车离开了黑线（过障碍、被顶起来、上坡腾空时都会这样）。

新任务里对应的块就是 **「等条件：探头全白」**。（以前我在页面上管这个叫"丢线"，你没看懂——**以后统一叫"探头全白"**，页面上也已经改过来了。）

### ③ 旧代码的转向函数，名字有一半是反的

`Haixin/Hardware/gyro_control.c:214-250`：

- `GyroControl_TurnLeft(a)`：`target_angle -= a` —— 真的是左转；
- `GyroControl_TurnRight(a)`：`target_angle += a` —— 真的是右转；
- 但是 **`GyroControl_TurnRightFixed()` 函数体里调的是 `TurnLeft(...)`**，`GyroControl_TurnLeftFixed()` 调的是 `TurnRight(...)` —— 这两个"固定角"函数**名字和行为相反**（函数上面的注释倒是和函数体一致，是名字写错了）。

新任务里只有「转角度」一个块，**正数 = 左转、负数 = 右转**（和操控页的说法一致）。转换时是按**旧函数名**翻的，所以**第一次上板一定要看拐弯方向对不对**（§5）。

### ④ 旧代码靠"死等毫秒"转向，新任务靠"角度到了就走"

旧代码转 90° 是这么写的：

```c
Toggle_Gyro_Control(1, 0, 0);        // 开角度环、速度 0
GyroControl_TurnLeftFixed();          // 目标角 = 当前角 + 固定角
HAL_Delay(700);                       // 死等 700ms，然后当它转完了
Toggle_Gyro_Control(0, 0, 0);
```

新任务的「转角度」块是**等角度误差进入容差（±2.0°）才往下走**，那个毫秒数只是"最多等多久"的安全网（超时了会打个超时标记但继续走）。

⇒ 所以新任务会比旧代码转得**准**，但**耗时不一定一样**（旧的 700ms 是拍脑袋的，新的是真等到位）。程序里的时间不能和旧版逐毫秒对齐，这是**故意的**。

## 1. 旧命令 → 新任务块（一张词典）

| 旧代码 | 干什么 | 新任务里的块 |
|---|---|---|
| `tracing_data[0..7]==0 && black_num==N` | 八路全白、且走到第 N 段 | 状态 N 开头的 **「等条件：探头全白」** |
| `black_num = M` | 下一段是 M | 状态末尾的 **「跳到状态」→ 状态 M**（最后一个状态写「结束任务」） |
| `Toggle_Gyro_Control(1, l, r)` | 开角度环，并给基准速度 | **「切换模式：角度环」+「设定速度」**（两个数是左右轮，取平均换算） |
| `Toggle_Gyro_Control(0, 0, 0)` | 关掉控制 | 不单独发（下一个块会重新定模式） |
| `Load(l, r)` | 直接给左右轮速度 | **「切换模式：两轮直给」左 l 右 r** |
| `Load(0, 0)` | 停 | **「设定速度 0」** |
| `Servo_Move(n)` | 摆第 n 套舵机动作（车上存的动作表） | **「舵机动作」#n**（后跟的 `HAL_Delay` 变成"后等 N ms"） |
| `GyroControl_TurnLeft/Right(a)` | 相对当前朝向转 a 度 | **「转角度」**（正=左、负=右） |
| `GyroControl_TurnLeftFixed/TurnRightFixed()` | 转固定角（旧板默认 10°，新板 90°） | **「转角度」±90** |
| `PID_Tracing_Timer_Start(); HAL_Delay(ms); ...Stop();` | 循迹跑 ms | **「切换模式：循迹」+「等待 ms」** |
| `HAL_Delay(ms)` | 死等 | **「等待 ms」** |
| `Buzzer_blink()` / `RGB_blink()` | 响一下 / 闪一下 | **没搬**（新任务只跑流程，提示音留给车上别的逻辑） |
| `renwu_flag = 3` | 全程结束 | **「结束任务」**（停车） |

刻度换算：旧板速度刻度满量程约 **1000**，新板 **7200**，即 **×7.2**（旧代码里的 `RW(900)` 就是新板的 **6480**，也就是 90% 油门）。左右轮数字不一样的地方（比如 `Load(RW(920), RW(880))`）取平均或按两轮直给原样搬。

## 3. 逐段对照

下面每段都按同一个格式：**旧代码怎么写** → **新任务里是哪些块** → **这段在干什么**。
（`RW(x)` 是旧代码里的刻度写法；舵机动作号 #n 是车上动作表里的第 n 套。）

> ⚠️ **下面每段的"块清单"是第一版（基准 6480、190 块）的原文**，第二版把速度刻度全换成基准 7000、
> 补了 3 段循迹、修正了几处"关角度环后的恢复速度"，并给状态名加了段号 —— 差异逐条列在 §0.5。
> 要看**第二版逐块的依据（含 `renwu.c` 行号）**，用 `python out\_dump_lap.py tools\console\web\src\lib\tasks\renwu-lap.json`
> 或看生成器 `out/_gen_lap2.py`（每条 DSL 后面都挂着出处行号）。

### S0 台阶2（主页） ← 旧 black_num 0、1

**旧代码**（`renwu.c:125-148`）
段 0：`Buzzer_blink(); Servo_Move(2); HAL_Delay(300);` → 段号 1
段 1：`Toggle_Gyro_Control(1, RW(900), RW(935)); Load(RW(900), RW(935)); HAL_Delay(450);` → `Servo_Move(3)` 等 700ms → `Servo_Move(2)` 等 600ms → `Servo_Move(4)` 等 600ms → `Servo_Move(5)` 等 1500ms → `Toggle_Gyro_Control(0,0,0)`

**新任务**（进门 1 块 + 循环 14 块）
`[进门] 切换模式 循迹+角度环`；循环：等「探头全白」→ 舵机动作 #2（后等 300ms）→ 等「探头全白」→ 设定速度 6606（≈92%）→ 切「角度环」→ 等 450ms → 舵机 #3（700ms）→ #2（600ms）→ #4（600ms）→ #5（1500ms）→ 切「循迹+角度环」→ 等「探头全白」→ 等 300ms → 跳到 S1 木刺

**在干什么**：进比赛后的第一段。上小型阶梯前先摆一次机械动作（#2），等车离开黑线（说明已经骑上台阶）再给油，用角度环走直线，边走边把 #3/#4/#5 三套动作摆完；再等到一次"探头全白"就认为台阶过完了，交给木刺段。

### S2 栅栏 ← 旧 black_num 4、6、7（旧代码里最绕的一段）

**旧代码**
段 4（`renwu.c:175-323`）：`Load(RW(920), RW(880)); HAL_Delay(300); Toggle_Gyro_Control(1,0,0); GyroControl_TurnLeftFixed(); HAL_Delay(700); Toggle_Gyro_Control(0,0,0); Servo_Move(2); Load(RW(-500), RW(-500)); HAL_Delay(800);` —— 中间是 120 多行（188~313）**被注释掉的循迹循环** `motor_tracing_pid(4.5); HAL_Delay(20);` —— 最后 `Toggle_Gyro_Control(1, RW(900), RW(960)); Load(RW(900), RW(950)); Servo_Move(3); HAL_Delay(500); Servo_Move(2); HAL_Delay(2050);`
段 6（`renwu.c:326-336`）：`Load(RW(900), RW(900)); HAL_Delay(450); Toggle_Gyro_Control(1,0,0); GyroControl_TurnRight(70); HAL_Delay(500); Toggle_Gyro_Control(0,0,0);`
段 7（`renwu.c:338-473`）：`Load(RW(900), RW(900)); HAL_Delay(500); Servo_Move(1); Toggle_Gyro_Control(1,0,0); GyroControl_TurnLeftFixed(); HAL_Delay(800);` —— 又是 110 多行注释掉的循迹循环（350~466）—— `Toggle_Gyro_Control(1, RW(900), RW(900)); HAL_Delay(3800); Toggle_Gyro_Control(0,0,0);`

**新任务**（循环 27 块，三段合成一个状态）
等「探头全白」→ 两轮直给 左6624 右6336 → 等 300ms → 设定速度 0 → 转角度 −90°（容差 2.0°，超时 700ms）→ 舵机 #2 → 两轮直给 −3600/−3600 → 等 800ms → 设定速度 6660 → 切「角度环」→ 舵机 #3（500ms）→ 舵机 #2（2050ms）→ 切「循迹+角度环」→ 等「探头全白」→ 两轮直给 6480/6480 → 等 450ms → 设定速度 0 → 转角度 −70°（超时 500ms）→ 等「探头全白」→ 两轮直给 6480/6480 → 等 500ms → 舵机 #1 → 设定速度 0 → 转角度 −90°（超时 800ms）→ 设定速度 6606 → 切「角度环」→ 等 3800ms → 切「循迹+角度环」→ 跳到 S3 减速带

**在干什么**：过栅格。三次"离开黑线"分别对应三个小段：先斜着走一下、左转 90°、倒一点；再给油直行并摆 #3/#2 两套动作；然后右转 70°、直行、摆 #1、再左转 90°，最后一段 3.8 秒直线跑过去。
**注意**：旧代码这里转向全是"死等毫秒"（§0④），新任务改成等角度到位，所以这一段的实际耗时可能和旧版不一样。

### S3 减速带 ← 旧 black_num 8（**旧代码里的死段**）

## 4. 转换时"改了什么 / 没改什么"

**没改（原样搬）**
- 所有慢动作顺序、每个 `HAL_Delay` 的毫秒数、舵机动作号（1~14）、转角度数（60/70/80/88/90）；
- 段与段之间的触发条件 —— 都是"探头全白"；
- 段号跳跃之后的**状态跳转**（跳到哪个状态和旧代码 `black_num=M` 一致，最后一段变成「结束任务」）。

**改了／没搬**
- **速度刻度**：旧板满刻度 1000 → 新板 7200。**换算基准取 `HP_TASK_SPEED`（`firmware/App/Svc/host_link.c:108`，当前 = 7000）**：
  `旧刻度 × 7000 ÷ 900`。所以看到「设定速度 7000」= 旧代码的 `RW(900)`；「3888」= 旧 `RW(500)`；「6222」= 旧 `RW(800)`；「7155/6844」= 旧 `Load(RW(920), RW(880))`。
  （⚠️ 第一版用的是 6480 = 7200 的 90%，那是 2026-10-06 之前的值；同一份 JSON 里所有速度都会随之差 ~8%，改 `task_speed` 之后要重跑 `out/_gen_lap2.py` 重新生成。）
- **「设速度/切模式」只在值变了才发块**：新解释器里这两个是**持续状态**（发一次就一直那样），所以旧代码里那些重复的 `Toggle_Gyro_Control(1, 900, 900)` 被合并掉了 —— 块数从 400 多行压到 190 块，行为不变。
- **转向**从"死等毫秒"换成"等角度到位"（§0④）——更准，但耗时不再逐毫秒对齐。
- **蜂鸣器/闪灯**（旧代码 36 次 `Buzzer_blink()`）**没搬**：新任务只跑流程。想要"响一下"得另外加（车上目前没有"响一下"这个块）。
- **死段没搬**：8（减速带）、12（方形通道）、14、15、16、20、22 —— 旧代码里根本进不去，所以新任务里也没有（减速带那段留了个空壳）。
- **减速带 S3 是空壳**（见 §3 S3）：要真过减速带，得自己往那个状态里加动作。

**体积**：15 个状态 / **208 块** / 镜像 **2434 字节** / CRC **0xCFC6**（第一版：15/190/2127 B）。单条任务上限 4096 字节（`firmware/App/Svc/task_run.h:19` 的 `TASK_RUN_MAX_PROG`、`task_store.h:70` 的 `TASK_STORE_CAP`），车上程序区总共 6144 字节（3 页 Flash）——这条任务占**单任务上限的 59%、程序区的 40%**，还剩不少地方。

## 5. 第一次上板要盯的几件事

1. **拐弯方向**（最重要，但**2026-10-07 已逐条核过、不用再试错**）。旧代码的 `TurnLeftFixed/TurnRightFixed` 名字是反的（两块板都是，见 §0.5），
   而任务块的「转角度」是**正数 = 左转、负数 = 右转**。核对的结论：14 处转向的 ± 号**全部与旧车的实际转向一致** ——
   `TurnLeftFixed()` → −90（右转）、`TurnRightFixed()` → +90（左转）、`TurnLeft(a)` → +a、`TurnRight(a)` → −a。
   上板时挑两处最容易看的复核：S2 栅栏的「转 −90°」应该是**右转**、S5 方通的「转 +80°」应该是**左转**；真反了就把那个块的度数取反（页面上点一下字段就能改，改完重新烧）。
2. **时间**。转向从"死等"变成"等角度到位"，S2/S5/S11 这几段动作密的，耗时和旧版会有差别；如果某段动作接不上（比如舵机还没摆完车就动了），把那个「等待 ms」调大一点。
3. **减速带 S3 是空壳**（§3 S3 / §4）—— 真要比这一项，得先往里加动作。
4. **倒车要等固件那一行修好**（§0.5 末尾）：6 处「两轮直给 负/负」现在上板是**原地打转**（`p2` 被当无符号读成 61936）。修好 `task_run.c` 的那 1 行之前，别指望这几段能倒车。
5. **5 处入口条件用的是条件 11（哪几路是白的）+ 掩码**，与旧代码的 `data[0..4]==0` 之类**完全一致**。
   代价是：这 5 块要求车上固件**带 `TASK_C_CH_WHITE`**（2026-10-07 新增，`firmware/App/Svc/task_prog.h:81`）。
   烧之前确认固件是那一版之后；否则那 5 段会一直等下去（车会继续循迹，按停车即可）。
   对照：整条任务 21 个入口里，另外 16 个是「8 路全白」（`COND.LINE_LOST`）。
6. **除了上面这些，还有几处"旧代码本身"与任务格式的能力差异**（都逐条记在 §0.5）：
   旧的两级循迹 `motor_tracing_pid(4.5)` 在任务里用三级串级（`SET_MODE 3`）代替；
   `PID_Tracing_Timer_Start();HAL_Delay(ms);Stop()`（旧板 TIM2 中断 10Hz、慢速基准）用「切循迹 + 等 ms」代替；
   旧 `Load()` 是开环 PWM，任务里的「两轮直给」走速度环闭环；
   旧代码左右轮基准不一样的地方（900/935、900/960、930/900）在角度环里只能取平均。

## 6. 顺手记一下上位机这次的改动（同一批活）

- 任务编辑器里**所有从固件注释搬来的内部编号都换成了人话**：`p0~p3`、`flags.bit0`、`0xFFFF`、`tracing_cross()`、`Motion_GetFault()` 这些不再出现在页面上；「丢线」改叫**「探头全白」**；速度的「PWM 刻度」改叫**「油门刻度」**并直接标百分比。
- **每个字段下面常显一行白话说明**，鼠标停上去还有完整提示框（下拉里每个选项也有）。
- IMU 页的「固件能力位 0xff（bit0 遥测…）」换成「车上支持的功能：遥测 · 动作表 · …」；调参页不再把 `speed_kp · id 0x601` 摆在明面上（固件键名和十六进制编号挪进悬停提示）。
- 还留在页面上没动的十六进制只有两类**数据**：参数指纹（`0xB157` 这种，4 个页面）和任务校验和（`0xA38C`）——它们是校验值本身，不是黑话，悬停里有解释。
