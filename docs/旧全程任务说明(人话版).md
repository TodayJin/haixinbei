## 0. 先记住三件事

### ① 触发条件只有一个：**8 路探头全压在黑线上**

旧代码每一段的开头都长这样：

```c
if (tracing_data[0]==0 && tracing_data[1]==0 && ... && tracing_data[7]==0 && black_num==4) {
```

★ **`tracing_data[i] == 0` 的意思是「第 i 路压到黑线了」，不是「白」。**（2026-10-07 才把这条钉死：上一版译成「全白」是**反的**。）
判据有四处，任一条都够：

| 证据 | 说的是什么 |
|---|---|
| `Haixin/Hardware/tracing.c:9-16` `tracing_data[i] = !HAL_GPIO_ReadPin(...)` | 它**取反**了 |
| `Haixin/Hardware/PID_tracing.c:18-25` 用**原值**当"这一路看见线" | 同板另一份读法不取反 |
| `firmware/App/Svc/host_link.c:496` `if (bsp_trace_bit(i)==GPIO_PIN_SET) m |= 1<<i;` 注释「1 = 压线」 | 原始电平 1 = 压线 |
| `docs/控制算法升级方案.md:42` 「`renwu.c` 里『全 0』事件 = 8 路原始位全 SET（**整排压线**）」 | 当年移植时写下的原话 |

所以：`tracing_data[0..7]==0` = **8 路全压在黑线上**（旧板 `motor_tracing()` 的注释也全都是这个口径）。

任务里用的是 **条件 10**，**页面上那一条下拉就叫「指定哪几路是黑的」**，后面的 8 个方框 = 8 路探头：

- 勾中的那几路**全部**压着黑线 ⇒ 满足；**没勾的一律不管**；
- 8 个全勾（掩码 `0xFF`）就是「8 路全压黑」；
- 一个都不勾（掩码 0）= 永远不满足（固件定死的，防手滑）。

下文主表里写「等 **8 路全压黑**」= 8 个方框全勾；写「等 **第 1~5 路全压黑**」= 只勾第 1~5 个方框（其余三个不管）。

### ② `black_num` 不是"黑线数量"，是"我走到第几段了"

段号是 `0→1→2→3→4→6→7→9→10→11→13→17→18→19→21→23→24→25→26→27→28`，
跳过的段号在旧代码里根本进不去（见 §3 的死代码）。**状态名里都带着段号**，就是为了让你按段号认路。

### ③ 数字怎么读

| 你看到的 | 什么意思 |
|---|---|
| **油门刻度** `7000` / `7200` | 0..7200 = 0..100%。**7000 = 97%**、`7200` = 100%、`3888` = 54%、`0` = 停 |
| 旧代码里的 `Load(900,935)`、`RW(900)` | 那是**旧板刻度**（1000 = 100%）。换算基准是参数 `HP_TASK_SPEED`（本次取 **7000**）：`旧刻度 × 7000 ÷ 900`，超 7200 钳位。例：旧 900 → 7000、旧 500 → 3888、旧 −500 → −3888 |
| **动作 N** | 车上存的那套舵机动作，见下表 |
| **转 +80° / −90°** | **正 = 左转、负 = 右转**（和操控页一致） |
| `等 300ms` | 就是死等 300 毫秒（旧代码的 `HAL_Delay`） |

舵机动作表（1..14 是旧板原样搬过来的，15..20 是新增占位）：

| N | 名字 | 舵机1 / 舵机2 | N | 名字 | 舵机1 / 舵机2 |

## 2. 旧代码自己带的坑（转写时按"当年车实际怎么动"办，不按作者字面意图）

1. **`TurnLeftFixed()` / `TurnRightFixed()` 名字和行为是反的。**
   `Haixin/Hardware/gyro_control.c:218-250` 逐行是：

   | 函数 | 行 | 函数体 | 实际转向 | 任务里的块 |
   |---|---|---|---|---|
   | `GyroControl_TurnLeft(a)` | H218 | `target_angle -= a` | **左转** | `+a` |
   | `GyroControl_TurnRight(a)` | H229 | `target_angle += a` | **右转** | `−a` |
   | `GyroControl_TurnRightFixed()` | H239 | 调的是 `TurnLeft(...)` | **左转**（名字说右） | `+90` |
   | `GyroControl_TurnLeftFixed()` | H247 | 调的是 `TurnRight(...)` | **右转**（名字说左） | `−90` |

   ⇒ 主表里凡是写「实际右转 / 实际左转」的地方就是踩在这个坑上；新任务里已按**实际方向**给 ± 号
   （14 处转向的 ± 号逐条核过）。

2. **大坡那一段（段24）的 `Load(0,0)` 是失效的（旧 H789）。**
   那一行执行时角度环还开着（旧 H785 开的），而旧板 10ms 中断里的 `GyroControl_Task()`
   （`Haixin/Core/Src/main.c:287-292` → TIM4）每拍都 `Load(基准±修正)` 把它**立刻覆盖**
   ⇒ **车当时根本没停**，继续按 900/900 走完那 500ms。所以任务里那一块是「两轮直给 7000/7000」而不是"停车"。
   同理，`Toggle_Gyro_Control(1,l,r)` 后面紧跟的 `Load(...)` 也都是被覆盖的（旧 H82、H261 等）。
   > 想要作者本意（真停 500ms），把那一块改成「切换模式：停车」即可 —— 但那就不是当年车的行为。

3. **旧代码有两套相反的循迹极性。** `tracing.c`（取反，`renwu.c` 用的）和 `PID_tracing.c`（用原值）在同一个工程里。
   `docs/控制算法升级方案.md:42`、`docs/上位机通信协议.md:181` 都记着这件事。**本任务跟的是 `renwu.c` 那一套。**

4. **旧板 `Servo_Move(10)`（高台）漏了 `break`**，会直接穿到 `case 11`（高台下），两个角度连着下发。
   好在 `renwu.c` 从头到尾**没调用过动作 10**，所以没影响；新板的动作表已经把 10 和 11 分开了。

5. **`PID_Tracing_Timer_Start/Stop` 不是"循迹开关"。** 旧板它开的是 TIM2 的 10Hz 后台中断，
   里面跑的是**慢速基准**（`speed = 200` = 20% 油门）的 `motor_tracing_pid_0(4.5)`。
   ⇒ 任务里用「切回循迹 + 等 N ms」近似，**基准速度不一样**（新板是三级串级 + 参数里的循迹速度），这一段不能逐毫秒对齐。

## 4. 这份任务**表达不出来**的东西（不是译错，是格式没这个能力）

| 旧代码 | 任务里怎么办 | 差别 |
|---|---|---|
| `motor_tracing_pid(4.5)`（两级：循迹+速度，直行 97 处） | 「切换模式：循迹」（= 三级串级 循迹→角度→速度） | 新的是三级串级，**转向行为比旧的两级更"咬线"** |

## 6. 什么时候该按"停车"

- 车停下不动、但循迹还在跑 ⇒ 多半是卡在某个「等条件」上（条件一直不满足）。按页面上的停止 / 车上任务页中键。
- 现在这一段要求的是 **8 路全压黑**：如果场地上的黑色标记比探头排还窄（8 路不可能同时压黑），这一段就永远等不到 —— 那是**触发条件本身**的问题，不是任务坏了。
