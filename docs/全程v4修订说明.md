> ⚠️ **这一条要重烧固件才生效**（老固件不读 `p0`）。长度不变（`p0` 是字段不是新块），
> 只有 CRC 变了：`0x1D0F` → **`0xE251`**。

## 1. 逐条明细

### A1 · 40 块假延时 → 真延时

**病根**：v3 的生成器把"等 N 毫秒"写成了

```json
{"op":6,"flags":0,"p0":9,"p1":0,"p2":<ms>,"p3":65535}     // WAIT_COND + 条件9(ALWAYS) + 超时
```

`firmware/App/Svc/task_run.c:290-320` 的语义是：条件成立（`cond_ok(9)` 恒 1）且 `flags&0x7F=0`（不要求持续）
⇒ `need=0` ⇒ `(s_now - s_hold_from) >= 0` **当拍成立** ⇒ `return 1`；
`p2` 那条超时出路（`:322`）**永远走不到**。⇒ 车上这 40 块耗时 **0 ms**。

**修**：`{"op":5,"flags":0,"p0":<ms>,...}`（`WAIT_MS`，`task_run.c:278-279` 才是真延时）。
**10 B 等长** ⇒ 单块字节数不变（总长变化只来自其他条目）。

**改动范围（40 块，逐状态被吞掉的时长）**：
上台阶 450 / 过木刺 1000 / 过栅栏 2180 / 栅栏右转 4750 / 过草地 2800 / 钻方通 5040 / 出洞口 700 /
十字A 1700 / 过U形隧道 900 / 路口B 500 / 十字C 1800 / 大坡 3500 / 十字D 2350 / 台阶3收尾 12500 = **40170 ms**。

> ★注意区分：**"等某个条件"的 `WAIT_COND` 一个都没动**（条件 3/6/10/11 的 24 块）。
> 判定条件严格限定为 `op=0x06 且 p0=9 且 flags=0 且 p3=0xFFFF 且 p1=0`，脚本里断言命中数正好 **40**。

### B2 · S6 掩码 `0x1F` → `0xF8`

### B3 · 删掉从死段 16 建出来的「出洞口」

  段 14/15/16（`L648-696`）没有任何分支把 `black_num` 设成它们 ⇒ **全是死段**。

- **重编号明细**（脚本自动做并断言无悬空）：十字A body[17] GOTO 9→8、过U形隧道 body[7] 10→9、
  路口B body[6] 11→10、十字C body[10] 12→11、大坡 body[27] 13→12、十字D body[11] 14→13；`main` 仍为 0。

### C1 · 补回段 2 / 段 11 两个锚点

旧代码这两个段是"上一个障碍做完 → 等下一个触发带"的锚点（`L150-156`、`L500-507`，各 3 行：
`Buzzer_blink(); HAL_Delay(300); black_num=…`）。v3 里没有对应块，这也是 B1 能抢跑的前提。

v4 把它们放在**上一个状态的尾部**（而不是下一个状态的 `enter`），这样：
① 与旧代码的位置一致（段 2 属于 `black_num==2`，是段 1 做完之后的事）；
② 新板的"过点蜂鸣"（`task_run.c:78-82`，进状态时响）落在**压上黑带那一刻**，而不是上一个障碍结束时；
③ 下一个状态自己的门（S1 的 `0xFF`、S6 的 `0xF8`）仍然在，**两道门都在**，与旧代码逐句对应。

| 位置 | 新增块 |
|---|---|
| 上台阶 body[16..17]（尾块 GOTO 之前） | `WAIT_COND 条件10 掩码0xFF 超时8000 → 继续` + `WAIT_MS 300` |
| 过草地 body[5..6]（尾块 GOTO 之前） | 同上 |

### C2 · `ACTION 5` / `ACTION 9` 展开中间姿态

### C4 · 大坡段补回 500 ms 停顿

`L853-856`：`TurnLeft(88); HAL_Delay(1000); Toggle_Gyro_Control(0,0,0); HAL_Delay(500);`
—— 此时 `saved=(0,0)`（`L852` 的 `Toggle(1,0,0)`）⇒ 是**真停**，车停着等 500 ms 才重新起步（`L859`）。

★这一处**不是**"关角度环会恢复保存的基准速度"那个坑（那个坑 v3 在 `L844` 那处已经译对了）。

### C5 · 只记一句：整体慢约 2.8%

旧 `motor_tracing_pid()` 的 `int speed = 1000`（`Haixin/Hardware/PID_tracing.c:45`）而旧板满刻度 1000
