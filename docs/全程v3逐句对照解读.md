## 1. 先把坐标系钉死（后面每一行都靠它）

### 1.1 极性：`tracing_data[i]==0` = 第 i 路**压到黑线**（独立复核，确认已定案）

```c
// Haixin/Hardware/tracing.c:9-16 —— tracing_data[] 的**唯一**赋值处
tracing_data[0]=!HAL_GPIO_ReadPin(GPIOA,GPIO_PIN_4);
... tracing_data[7]=!HAL_GPIO_ReadPin(GPIOE,GPIO_PIN_8);
```

```c
// Haixin/Hardware/PID_tracing.c:18-25 —— 同一批引脚，**不取反**，且注释写明"1 = 检测到信号"
if (HAL_GPIO_ReadPin(GPIOA,GPIO_PIN_4) == GPIO_PIN_SET) {L1 = 1; num++; ...}
... data = (L1*1+L2*2+...+R4*8)/num;   // 目标 4.5 = 中线
```

- `tracing_data[i]==0` ⟺ 引脚为 SET ⟺ `PID_tracing.c` 口径里的 **1**（"在线"）。
- ⇒ `tracing_data[0..7]` **全 0** = 八路全为 SET = **整排压线**（宽黑带）。
- 与 `docs/控制算法升级方案.md:42`「renwu.c 里『全 0』事件 = 8 路原始位全 SET（整排压线）」一致；
  与 `firmware/App/Svc/host_link.c:496`「1 = 压线」、`trace_cal.h`「1 = 压黑线」口径一致。
- ⇒ v3 用**条件 10 `CH_BLACK`**（勾中的那几路**都是黑的**）**方向正确**。这一条 v3 没有踩坑。

掩码对应关系（`task_prog.h:95-98`：bit0..bit7 = 第 1..8 路）：

| 旧写法（`renwu.c`） | 真正看的路 | 正确掩码 | v3 落地的掩码 |

| `data[0..7]==0`（20 处） | 全部 8 路 | `0xFF` | ✓（S0/S4/S11/S12/S13/S14） |

### 1.2 刻度换算 `RW()`

```c
// renwu.c:34-41
static int task_pwm(int old_scale) {
    int base = (int)host_param_get(HP_TASK_SPEED, 6480.0f);   // 车上默认/上位机镜像都是 7000
    if (base < 0) base = 0;  if (base > MOTOR_PWM_MAX) base = MOTOR_PWM_MAX;
    return (old_scale * base) / 900;
}
#define RW(v) task_pwm(v)
```

- 旧板满量程：`Haixin/Core/Src/tim.c:203-205` `TIM8 PSC=71 / Period=1000-1` ⇒ 1 kHz、**满刻度 1000**。
- 新板 `MOTOR_PWM_MAX = 7200`。基准取 `HP_TASK_SPEED`（`firmware/App/Svc/host_link.c:108` 默认 **7000**，
  `tools/console/bridge/params.py:34` 镜像也是 7000）⇒ `RW(v) = v×7000÷900 = v×7.7778`。
- **注意**：`RW()` 只对 `base` 做了 `0..7200` 钳位，**返回值本身不钳位**；超 7200 由 `Load()`/`Limit()` 在电机层夹到 7200。

### 1.3 两块板的四处"同名不同义"（这是最容易整段译错的根源）

| 项 | 旧板 `Haixin/` | 新板 `firmware/` | 对译的影响 |
|---|---|---|---|
| `GyroControl_TurnLeft(a)` | `target = NormalizeAngle(target - a)`（`gyro_control.c:218-223`） | `target = NormalizeAngle(target + a)`（`gyro_control.c:1069-1072`，注释「偏航角增大 = 向左」） | **同一句源码在两边转的方向相反** |
| `GyroControl_TurnRight(a)` | `target + a`（`:229-234`） | `target - a`（`:1078-1081`） | 同上 |
| `TurnLeftFixed()` / `TurnRightFixed()` | 交叉调用：`TurnRightFixed(){TurnLeft(90);}`、`TurnLeftFixed(){TurnRight(90);}`（`:239-250`） | **一模一样**的交叉（`:1087-1098`） | 名字与函数体相反，但**两边反得一样** ⇒ `*Fixed()` 系列的**名字是对的**（双反） |
| `Load()` 的轮子符号 | 直接写 CCR，右路 `b=+moto2` | `b = -moto2`（`motor.c:38-48`，右电机镜像安装的补偿） | 两边对外语义都是"正 = 该轮前进" |

**由此得到一条不需要假设任何物理方向的判据**（本文 A2 就用它）：

> `firmware/App/Svc/task_run.c:253-255` 里 `TURN_DEG(p1)` 做的是
> `target = NormalizeAngle(当前航向 + p1)`，即 **`TURN_DEG(+p) ≡ target += p`**。
> 旧板 `GyroControl_TurnRight(p)` 也是 `target += p`。
> ⇒ **`TURN_DEG(+p)` 与旧板 `TurnRight(p)` 是同一个动作**；
> ⇒ 旧板 `TurnLeft(p)`（`target -= p`）必须译成 **`TURN_DEG(-p)`**；
> ⇒ 旧板 `TurnLeftFixed()`（= 旧 `TurnRight(90)` = `target += 90`）译成 **`TURN_DEG(+90)`**；
> ⇒ 旧板 `TurnRightFixed()`（= 旧 `TurnLeft(90)`）译成 **`TURN_DEG(-90)`**。

旧作者自己在 `renwu.c` 里的注释也印证了这个反号：`TurnRight(60)` 后面写「//左转90」（`L705-707`、`L743-745`）、
`TurnRight(80)` 后「//左转90」（`L807-809`）、`TurnRight(88)` 后「//左转90 / //zuozhuan」（`L828-830`、`L876`）、
`TurnLeft(80)` 后「//右转90」（`L782-784`）——**7 处里 6 处支持"普通 Turn 名字是反的"**，
而 `TurnLeftFixed()` 后写「//左转90」（`L547-549`、`L585-588`）、`TurnRightFixed()` 后写「//右转90」（`L723-725`、`L901-903`）
——**支持"`*Fixed()` 名字是对的"**。唯一一处与名字一致的注释是 `L527-529`（`TurnLeft(80)` 后写「//左转90」），
已在 §6 存疑清单里单列。

## 3. 用户点名的 6 个易错点，逐条答复

**① 极性** —— ✓ **v3 对了**。`tracing_data[i]==0` = 该路压黑（§1.1 独立复核：`tracing.c:9-16` 取反 ⟺ `PID_tracing.c:18-25` 的"1 = 在线"）。

  = 旧刻度 200/1000 = **20% 占空比** ⇒ 新板等效 ≈ `RW(200)` = **1556**（或按占空比 20%×7200 = 1440）。
- **新**：S6 `body[5]` `SET_MODE 3`（循迹，基准 7000）、S9 `body[5]`、S13 `body[9]` 同样。
- **差异**：A1 修好后，这几段会以 **7000**（97%）冲出去，而旧车是**慢慢爬**（20%）。距离差 ~4.5 倍。
- **严重程度**：★（方通里冲太快 = 撞；U 形隧道入口亦然）。
- **建议**：这几段不要用 `SET_MODE 3`（它绑定全局基准 7000），改成"两轮直给 ≈1556/1556"+ `WAIT_MS`，
  或先 `SET_SPEED 1556` + `SET_MODE 2`（`TASK_MODE_TRACE`，`motion.c:174-176` 用 `motor_tracing_pid_speed(s_base)`，基准就是 `SET_SPEED` 那个值）。

### ★ C4 S12 少了 `L855-857` 的 500 ms 停顿（**不是**"恢复基准速度"那个坑）

- **旧**：`L853-854` `TurnLeft(88); HAL_Delay(1000);` 在 **base 0**（`L852` 的 `Toggle(1,0,0)`）下原地转；
  `L855-857` `Toggle_Gyro_Control(0,0,0)`（此时 `saved=(0,0)`）→ `Load(0,0)` → `HAL_Delay(500)`
  ⇒ **车停着等 500 ms**；`L859` 才 `Toggle(1, RW(900), RW(900))` 重新起步。
- **新**：S12 `body[10]` `TURN_DEG +88` 之后直接 `body[11]` `SET_SPEED 7000` + `body[12]` `SET_MODE 1`
  ⇒ **没有那 500 ms 停顿**，车比旧代码早 0.5 s 起步（修好 A1 之后这段是 1100 ms 的实走，位置会整体前移）。
- **严重程度**：★（500 ms × 7000 刻度 ≈ 半米；在大坡上可能影响 `Servo_Move(13)` 的落点）。
- **建议**：在 `body[10]` 与 `body[11]` 之间插一块 `WAIT_MS 500`（`op=0x05, p0=500`），并把 `body[11]/body[12]` 保留为"重新起步"。
- ★**顺带更正一个容易误判的点**：`Toggle_Gyro_Control(0,0,0)` 会 `Load(saved_l, saved_r)`（`renwu.c:76`），
  这看起来会让"关角度环"变成"继续走"。逐处核过之后：**除了 `L847` 那一处，其余 20 多处的 `saved` 都是 `(0,0)` 或立刻被下一句/主循环下一圈的
  `motor_tracing_pid()` 覆盖**，所以真正需要"按继续走译"的只有 `L844-852` 那一处 —— 而 **v3 那一处译对了**（`body[4]` 是"继续走 500 ms"而不是停车，`body[5]` 才把基准设 0）。

### ★ C5 旧循迹基准 = 满量程 1000，v3 用 7000

- **旧**：`motor_tracing_pid()` 的 `int speed = 1000`（`Haixin/Hardware/PID_tracing.c:45`）而旧板满刻度 1000（`tim.c:205` `Period=1000-1`）
  ⇒ 常态循迹是 **100% 占空比**；`RW(1000)` = 7778 → 电机层夹到 **7200**。
- **新**：`SET_SPEED 7000`（= `RW(900)`）贯串全流程。
- **差异**：循迹速度比旧车低 **2.8%**；所有 `RW(900)` 出身的直行段同理。
- **严重程度**：★（时间尺度整体略慢；对"抢时间"的赛项有意义）。
- **建议**：要么把这几段的 `SET_SPEED` 提到 7200，要么把 `HP_TASK_SPEED` 调到 7200 后**重新生成**（注意 v3 的数字是烘焙进去的，改参数不会自动跟随）。

## 5. 「表达方式不同（行为相同）」的典型例子（这些可以放心）

1. **`Buzzer_blink()` → "过点蜂鸣"**（`renwu.c` 里 20 多处）：新板 `task_run.c:78-82` 在**每次切状态**时
   `if (g_cfg.beep_marker) AppUi_Beep(20)`，而 `g_cfg.beep_marker` 真机默认 **true**（`app_stub` 也照抄了这个默认值）。
   旧代码的蜂鸣位置几乎都紧跟在"等到条件"之后，与"切状态"重合度高 ⇒ 大体对得上（少响/多响的具体次数见 §2 各行）。
2. **`Servo_Move(n)` ↔ `ACTION #n`**：除 5/9 号外，动作表 1..14 的终点角度**逐项一致**（`servo.c:175-189` vs `Haixin/Hardware/servo.c:50-124`），
   `ACTION` 的 `p2` 等待 = 旧 `HAL_Delay` 的值 ⇒ 这一层是干净的。
3. **`GyroControl_TurnX(); HAL_Delay(ms)` ↔ `TURN_DEG`**：旧的是"拍脑袋毫秒"（700 ms ≈ 73°），新的是"真等到 0.8° 内"。
   耗时不同（新版更短），但**目标朝向一致**、而且不会因为电池/地面不同而少转 17°——这是有意的升级（6 处 `*Fixed()` 派生的转向就是靠它才对上的）。
4. **`Load(l, r)` ↔ `SET_MODE 4` 两轮直给**：数值一一对应（§1.2）；区别只是旧的开环写 CCR、新的走速度环闭环。
   同一刻度下"新的更贴设定值"，属于能力提升不是错译。
5. **`PID_Tracing_Timer_Start(); HAL_Delay(ms); Stop();` ↔ `SET_MODE 3` + 等待**：结构上确实是"那段时间在循迹"，
   但**速度口径要按 C3 修**（旧是 20% 占空比）。这一条只对了"一半"。
6. **`renwu_flag=3`（切 C 流程）↔ `END`**：都表示"这一趟跑完了"，`END` 还会保证停车（`task_run.c:340-344`）。

## 6. 仍然存疑（静态读码判不了，必须实验或问人）

1. ★**`L527` 那处注释与函数名一致**：`GyroControl_TurnLeft(80)` 后面紧跟「`//左转90`」（`L527-529`），
   而另外 6 处同类注释都支持"名字是反的"（§1.3）。两种可能：① 注释抄错；② 作者在方通这一段**真的想要左转**。
   它决定 S6 `body[4]` 该写 `+80` 还是 `−80`。**30 秒可判**：把车放在地上，用操控页按一次 A（正转向 = 左，见 `PROJECT.md`），
   看车头往哪边转 —— 若"正 = 左"，则旧 `TurnLeft(80)` = `target −= 80` 是右转 ⇒ 应写 **−80**。
2. **两份任务在 6 个转向位置上互相矛盾**（v3 vs `renwu-lap.json`：6 处 `*Fixed()` 派生的一正一负，另有 8 处普通 Turn 两份**同样都反**，见 §4 A2）。至少要人工拍板一次"以哪份为准"，
   否则后面每次改动都会在两者之间来回翻。
3. **转向的实际机械滞回**：`TURN_DEG` 的出口判据是"航向误差 ≤0.8°"，但车体停下来之后还会有惯性/回弹；
   旧代码的"500 ms/700 ms"里包含了这段回弹的余量。要不要在 `TURN_DEG` 后再加"需持续"（已有 5 处加了 300 ms），
   得看实测的超调。
4. **减速带判据（S4）的物理前提**：v3 假设"两片减速带在灰度上算黑、且中间有一段整排白"。
   规则文档只写了尺寸（`docs/全地形机器人比赛规则与场地.md`），没写材质灰度。**必须实测**（把车摆上去看逐路原值）。
5. **`ACTION 5/9` 中间姿态的实际作用**：135/170 那一下对 2 级台阶是否必需，只有实车能答（C2）。
6. **节拍差异**：旧角度环 100 Hz（TIM4 10 ms）、旧主循环循迹节拍不固定（还夹着 OLED 刷新）、
   新解释器 5 ms 一拍 + 角度环 200 Hz + 循迹串级 200 Hz。同样的"毫秒数"在两种节拍下走出的距离不可能逐位相同，
   这一层无法用静态代码判定，只能靠实测标定（例如给每个段配 `DIST_MM` 条件而不是毫秒）。
7. **旧板 `motor_tracing_pid_0` 的 `speed=200`** 是源码事实，但当年是否与实际烧录的固件一致、有无现场改过，无法从仓库判定（车已不在）。
8. **`HP_TASK_SPEED` 在车上的真值**：v3 的数值按 7000 烘焙（与固件 SPECS/上位机镜像默认值一致），
   但车上 NVRAM 里的实际值没读（本轮不许碰车）。**上电后应核对一次**：若它不是 7000，§1.2 的换算基准就不成立，
   `renwu-lap.json`（运行时 `RW()` 口径）与 v3（烘焙口径）会跑出不同的速度，而 v3 不受参数影响。
9. **机械/电源层面的"跑不出设定速度"**：`DECISIONS.md` 里已实测"转速天花板 ≈80~85°/s""差速翻倍而转速不变（打滑）"，
   所以 `TURN_DEG` 的"到位时间"会比几何估算长；这不影响正确性，但影响总用时与超时余量（2500 ms 够不够，需实测）。
