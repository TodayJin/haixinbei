# 灰度（8 路模拟量）标定与检验

对应需求：用户 m05894「你完善一下标定流程我要检验一下」。
代码：`firmware/App/Svc/trace_cal.c` / `firmware/App/Svc/trace_cal.h`（逻辑）、
`firmware/App/Src/app_ui.c`（循迹页显示与按键）。

## 1. 现场怎么标

1. 进循迹页：标题「**循迹** `<数据源>` 中键标定」，页名右边那个单字 `普`/`亚` = **现在屏上、也是待会儿要标的那一套**。
2. **想对比另一套 → 按右键**：立刻换成另一套来显示（柱状图、`普`/`亚` 标记、当前判线参数一起变）。
   这一下**只动 RAM**：不写 Flash、不弹「保存成功」，掉电也不用记 —— 用户 m09558 明确这一页
   只是"看两套标定各是什么效果"，真正跑任务时用哪一套由任务程序自己调
   `trace_cal_select_set()` 决定，不靠这里的按键。
3. **想看数值本身 → 按下键**：在「柱状图」与「灰度原值/质量」两个视图之间来回切 ——
   两个视图都能直接按中键进标定（用户 m09335 定的手感）。
4. **中键** → 直接进标定，写进**当前这一套**；标题变「全黑按中键」，**右上角写全名
   「普通」/「亚克力」**，这一按标的是哪一套一目了然（用户 m09876：标定只有一个入口，
   必须让人看得出目标）。若此刻显示的不是你想标的那套：按左键退出 → 按右键换套 → 再按中键。
   然后**把车放到全黑处，按中键**。
5. 标题变「全白按中键」：把车放到**全白**处，按中键。
6. 标题变「标定完成」+ 右侧 `好路数/8`（例 `8/8`）。
   - 有坏路时右上带 `!`（例 `7/8!`），3 秒后自动回柱状图。
   - 失败时常驻标题「标定失败」+ 原因「黑白太近」或「无模拟量」，按任意中键/退出回空闲。
7. **想退出 → 按左键/上键**（标定中按左键 = 取消标定，仍在循迹页）。

**按键为什么这么怪**：框架只给页面三键 —— `firmware/App/Src/app_ui.c:513-538` 把
**上/左**折成 `UP`、**下/右**折成 `DOWN`，分不出左右。而循迹页要同时区分"右键切套"和
"下键换视图"，所以这一页像电机测试页一样**自己读五向键原始位图**
（`app_ui.c:495-511`，bit0上 bit1下 bit2左 bit3右 bit4中），只在"新按下"那一下动作
（`trace_key_scan()`，20ms 消抖）。中键仍旧走框架的 `OK` 事件。

**"现在默认是哪一套"**：进循迹页时**一律先回到第 0 套（普通）**（用户 m09558："默认就看普
通的"）；之后按右键的换套**只在这块屏上有效**，不落盘、也不影响任务程序的选择。
`nvram` 记录里那个 `cal_set` 字节仍然保留（v4 布局不动），但**没有任何地方再写它**，
所以它一直是 0 —— 复位后照旧从普通开始。

**两套标定（普通 / 亚克力，2026-10-01 用户 m07888 第 3 点）**：两套各自独立存 8 路的
黑/白/阈值/抖动（nvram 记录 **v4**：`cal` = 第 0 套、`cal_b` = 第 1 套、`cal_set` = 旧版
"当前用哪套"的遗留字段）。选哪一套有两条路：循迹页的**右键**（只看，不落盘）、
任务程序调 `trace_cal_select_set()`（真正决定跑任务用哪套）。设置菜单里原来那个
「标定套」项已按用户 m09558 删掉。
**"哪一套"在屏上怎么写**：循迹页标题行位置挤（`循迹` + 数据源 + `中键标定` 已经排满），
只放单字 `普`/`亚`；标定向导的「全黑/全白按中键」两个状态右边是空的，**写全名**「普通」/「亚克力」
（`draw_cal_set_name()`，用户 m09876）；`标定完成/失败` 右边要报质量或原因，仍只用单字。
**切套不需要"重新起头"**：自适应删掉后判线层没有任何跨帧状态，每路的阈值/柱高都直接来自
**当前这一套**标定的黑/白值（`s_thr`/`s_sp`/`s_rq` 在切套时就地重算），切过去立刻生效。
从没标过的第 1 套被切到时**先复制当前这一套**（`s_other_ok == 0` 时），不会切出 span=0 的野值。

每一步按下瞬间**同步采 32 帧（约 20 ms）**，不是"按一下就收下"：

| 判据 | 常量 | 值 | 不满足时 |
| --- | --- | --- | --- |
| 单点抖动（见下） | `TRACE_POINT_JIT_MAX` | 80（原值刻度） | **整点作废**，状态留在原档，标题「不稳!重按」，请重按 |
| 黑白跨度 | `TRACE_MIN_SPAN` | 32 | 该路 `TRACE_BAD_SPAN`(1)，画 `!` |
| 抖动 vs 跨度 | `jit*3 >= span` | — | 该路 `TRACE_BAD_JITTER`(2)，画 `!` |
| 至少 1 路可用 | — | — | 全坏 → `标定失败` |
| 建议可用路数 | `TRACE_QUALITY_MIN` | 6/8 | 只作为对外提示，不阻断 |

**「抖动」到底怎么算**（`robust_mean()`，`firmware/App/Svc/trace_cal.c:111-134`）：
按下的那一次连采 32 帧，对每路把这 32 个数**插入排序**，然后**掐掉两端各 `TRACE_CAL_TRIM`(=4)
个极值**，均值取 `v[4]..v[27]`（24 个数的平均），抖动 = `v[27] - v[4]`。
即 **抖动 = "中间 24 个的 max−min"**，不是全 32 个的 max−min（掐两端就是为了不被
一两个毛刺帧顶爆）。黑点、白点各算一个抖动，每路最终记**两点里较差的那个**
（`trace_cal.c:292-293`）：`if (jit[i] > s_jit[i]) s_jit[i] = jit[i];`。
两个门槛用的都是这个 `s_jit[i]`：单点闸门（80）在采完一点时判，逐路判定（`jit*3 >= span`）
在两点的数据都有了时判。

每路阈值 = `(黑值 + 白值) / 2`，极性 `pol` = 黑比白原值大。
未标定过的路 `trace_cal_bad_reason()` 返回 `TRACE_BAD_NOSAMPLE`(3)。

## 2. 屏上怎么检验（**下键** = 「灰度原值」检验视图）

循迹页按**下键**切到检验视图（空闲时才能切，标定中标题要留给提示语；再按下键切回柱状图）：

```
灰度原值                       好 8/8      <- 未标定「未标定」；这帧判丢线时改「丢线」
 294  328  310  196                        <- 8 路原始值，两行四列
 248  331  358  329                        <- 无效路在数字右侧画 '!'
位置4.5 黑240                               <- 送给 PID 的加权重心 + 本帧最黑那路的黑度
```

最后一行随这一帧的状态五种样子（判据见第 3 节）：

| 这一帧 | 最后一行 | 含意 |
| --- | --- | --- |
| `TRACE_FRAME_OK` | `位置4.5 黑240` | 位置 = 送给 PID 的加权重心（1..8，车在线上正中 = 4.5）；黑 = 本帧最黑那路的黑度 0..255（还剩多少对比度，"亚克力上还有没有对比度"就看它） |
| `TRACE_FRAME_WEAK` | `丢线 黑%u 噪%u` | 8 路**一路都没越过标定阈值**：这一帧没看到线，不给位置（界面柱子按住上一帧） |
| 没模拟量 | `现196~358 无模拟量` | 数字口 / 读不通，退回范围摘要 |
| 没标定 | `现196~358 未标定` | 没有阈值可用，退回范围摘要 |
| 其它回落 | `现196~358 差%u` | 差 = 有效路里最小的黑白对比度（不是"跨度"：跨 不在字模子集里） |

- 「好 n/8」= `trace_cal_quality()`；「差 d」= `trace_cal_min_span()`（只统计有效路）。
- 原始值是模块回的大端 16 位原样，**没做任何归一化**，标定前后都能看。
- 判读要点：车压在线上时，**压线那几路原值应明显低于两侧**。本机实测（车停在线上、未标定）
  `289 323 318 201 241 316 352 330`，最低的是第 4、5 路 = **正中间**，与官方 SDK
  `case 0x18`（D4+D5 = 正中间位置）一致 ⇒ 模块装反/接反时会在这里露出来。
- 柱状图页（按下键切回）里每根柱子上那条 XOR 线就是标定出来的阈值，底下一行是**实际参与运算**的
  0/1（已含「循迹反转」）。有 `!` 的那几路数字带 `!` 后缀。
- **版面约束（改这个页面前先看这条）**：`kk_font_body` 一屏竖直只放得下 3 行字
  （标题 y=1、原值 y=16/y=29、末行 y=44 已经是第 4 行但 y=44+12≤56 够）；
  y=41 和 y=53 这两行**会互相压字**（实测），所以末行只能有一行、y 用 44。
  另外本工程链的是 **newlib-nano，`snprintf` 的 `%f` 不支持**（静默输出空串），
  小数只能自己拆成整数打印（见 `app_ui.c` 里 `位置%u.%u` 的写法）。


## 3. 循迹判线：标定阈值 + 离阈值的距离（2026-10-05 用户 m31902 整改后）

**来龙去脉**：原来这一层跑的是「单帧自适应」——每路白底基线慢学（+四道闸门+硬夹子）、每帧整体
偏置 ŝ（残差中位数 + 限速 + jolt 判扰动）、最小对比度闸门。用户 m31902 的判词：

> 「你把这个"自适应"还是删除了吧，我感觉没有用…你还不如去优化一下之前说的那个阈值，可以把它
> 设为一个区间之类的…如果非要细分，也可以根据它离阈值的距离来确定中间的位置」

现场证据（2026-10-05，用户 m31580）：车明明白白摆在线上，帧却在 OK/WEAK 之间跳 —— WEAK 那一拍
**全是 `white_ref == 0` 触发的**（本车标定白值当时漂了 ~50 个计数），WEAK 一按住 500 ms 到期，
界面 8 根柱子整个塌成 0，就是用户看到的「丢线 / 全是零」。跨帧状态一多，判据在现场就互相打架。
⇒ 删掉：`s_base[]`/`s_base_ok`（每路白底基线）、`s_shift`/`s_shift_ok`（ŝ）、`s_dr`（漂移半径）、
jolt 判扰动、`TRACE_ADAPT_MIN_LEVEL/SHIFT_STEP/JOLT` 三个宏、饱和黑/白底计数兜底。
代码净减 1312 字节（text 117956 → 116644）。**设置页那一项也从「自动判线」改名「连续判线」**，
名字现在只表示"连续插值 / 纯 0/1"两种口径，不再是"开不开自适应"（改名 + 重新生成字模补
连/续 两字，2026-10-05 用户 m32216，见第 5 节）。

### 3.1 现在只有一条路：阈值 + 距离

每 20 ms 跟着一帧模拟量算一次（`frame_compute_body()`，`firmware/App/Svc/trace_cal.c:623-700`），
结果缓存进 `s_fl_lvl[]`（8 路柱高 0..255）+ `s_fl_state`；界面和循迹环读的是**同一份**数。

标定量只有：`s_blk[i]`（黑）、`s_wht[i]`（白）、阈值 `s_thr[i] = (s_blk+s_wht)/2`、
极性 `s_pol[i] = (s_blk > s_wht)`、抖动 `s_jit[i]`、坏路 `s_bad[i]`。

```
d   = s_pol[i] ? (raw - s_thr[i]) : (s_thr[i] - raw)   // > 0 = 越过阈值 = 黑侧
mag = min(|d|, 2047)                                    // 夹住防溢出（raw 最大 65535）
off = (mag * s_rq[i]) >> 12                             // = 255 * 距离 / 本路跨度
lvl = (d >= 0) ? 128 + off : 128 - off                  // 夹 0..255
```

* **128 = 正好压在标定阈值上** —— 也就是 0/1 的那条判定线，正好画在柱子半高；
  `off` 涨到半个跨度（= 标定黑值/白值）时饱和到 **255 / 0**。
* 所以阈值不是一根线而是一段区间：白侧 `[标定白值, 阈值]`、黑侧 `[阈值, 标定黑值]`，中间由
  **离阈值的距离**插值出来 —— 用户 m31902 原话要的就是这个。要"更窄的区间"就重标一次让跨度
  更接近实际（阈值永远是中点，区间宽度 = 跨度）。
* **白值漂几十个计数不再有害**：白地比标定白值亮/暗 50 个计数，只是柱高在 0 附近动 50 个数，
  判定线恒在 128 不动，不会再「整批滑到阈值另一侧」。这是删掉自适应的直接收益。
* 关掉设置页的「连续判线」（`trace_adapt_enable = 0`）就退回纯 0/1：`lvl = (d >= 0) ? 255 : 0`
  （老的中点阈值二值法，留着是为了能一眼看到"二值化之后是什么样"）。

**判据只有一条**：`black_thr`（越过阈值的路数）= 0 ⇒ 这一帧一路都没看到线 ⇒
`TRACE_FRAME_WEAK`（8 路柱高全 0、判定口按丢线、界面按住上一帧）；否则 `TRACE_FRAME_OK`
（好帧顺手存一份柱高快照给「丢线时按住上一帧」）。
"探头底下整片一个样"（离地 / 全黑地面 / 整片脏）**不在这层判** —— 那是循迹层
`firmware/App/Svc/PID_tracing.c` 的 `TRACE_UNIFORM_MIN`(0.75) 的活：本帧最亮那一路也得暗到
最黑那一路的 0.75 倍以下，才算"有明暗结构 = 有线"，否则判丢线。两层分工写死，
就不会再出现"车明明在线上、这一层先把自己判死"（m31580 / m31902）。

**给 PID 的权重**（`trace_cal_frame(float w[8])`）：`w[i] = (lvl > 128) ? (lvl-128)/127 : 0`
—— **只算越过阈值的部分**。为什么不用对称黑度当权重：白底一漂（本车实测漂 ~50 计数，而每路
跨度只有 85~165），`w = lvl/255` 下每根白路也能拿 0.25~0.49 的权重，把重心往 4.5 拽，
现场表现正是用户 m31048 说的「明明偏了却直着走」。只取越过阈值的部分后**白侧权重恒 0**，
不引入任何学习/自适应，也正是 m31902 要的"输出 0/1 就够了，要细分就按离阈值的距离"。
`PID_tracing.c` 那边配套的 ⓪ 判据一个字没动：
`if (wmax <= 0.0f || wmin > TRACE_UNIFORM_MIN * wmax) { lost = 1; on = 0; }`。

**没模拟量 / 没标定 / 这一路标定无效**：`TRACE_FRAME_FALLBACK` —— 界面按住上一帧好帧
（`trace_cal_disp_level()`，超时归零，另打「丢线」标记），判定口按丢线走；用户显式选
「灰度接口 = 数字量」时回落 `bsp_trace_bit()`；标定无效的路仍走 `level_of(idx, raw)` 那段旧的
中点阈值口径（`trace_cal_channel/level/thr_level` 里的兜底分支，只在没标定时用）。

### 3.2 几何缓存与实时性（参数全部由标定算出来，用户 m07689）

标定一变（向导收尾 / Flash 恢复）就重算一次，之后每帧只剩乘 + 移位：

| 量 | 公式 | 本车实测 | 干什么用 |
| --- | --- | --- | --- |
| `s_sp[i]` | \|黑白跨度\| | 108 150 169 156 148 142 130 93 | 换算的分母 |
| `s_rq[i]` | (255<<12)/跨度（定点倒数） | 9671 6963 6180 6695 7057 7355 8034 11231 | `off = (mag*s_rq)>>12`，每帧不做除法 |
| `s_an[i]` | max(跨度/8, max(16, 3×抖动)) | 16 18 21 19 18 17 16 16 | 只喂调试口 `white_ref`（判据已经不用它） |

`frame_compute()` 外面套了 DWT 计时壳：`trace_frame_cycles` / `trace_frame_cycles_max`
（170 MHz 下一个周期 5.88 ns）⇒ **实测 1276 周期 ≈ 7.5 µs/帧**，每 20 ms 一次 = 主循环的 0.04%
（自适应还在时典型 2377 周期，删掉后省了接近一半）。

## 4. 上位机自动判据：`out/_gray.ps1`（只读 SWD，不动车）


```powershell
pwsh -File out/_gray.ps1                 # 打印状态 + 实时原值 + 逐路黑/白/跨度/抖动/阈值/极性/判定 + 6 条判据
pwsh -File out/_gray.ps1 -Watch 5        # 连读 5 帧看峰峰（判断数据稳不稳）
pwsh -File out/_gray.ps1 -IntervalMs 100 # 帧间隔
```

退出码 = **不通过的判据条数**（0 = 全过），可以直接串进脚本。

6 条自动判据：

1. 8 路都标定过（黑值白值都不为 0）；
2. 每路跨度 ≥ 32（与 `TRACE_MIN_SPAN` 同值，改了一处要同步改另一处）；
3. 每路跨度 ≥ 3×抖动；
4. 8 路极性一致；
5. 实时原值落在各自标定区间内；
6. 压在线上的是中间那两路。

## 5. 改界面文案前必须查字（血泪教训）

```powershell
node tools/font/check_charset.mjs firmware/App/Fonts/kk_font_body.c "要查的字符串"
```

`kk_font_body` 是**子集**字模，**子集外的字会被静默跳过**（不报错、也不画方框），
现象就是标题少几个字。本次就踩了：旧文案缺 **跨 U+8DE8、小 U+5C0F、抖 U+6296**
（FAILED 态实屏原本是「标定失败 度太」）。已改成：

- `现%u~%u 跨%u` → **`现%u~%u 差%u`**
- `抖!重按` → **`不稳!重按`**
- `跨度太小` → **`黑白太近`**

## 6. 辅助工具与已知未决

- `out/_gray.ps1`：读标定结果与实时原值（上面第 4 节）。
- `out/_base_read.jlink`：一条 J-Link 命令读判线的内部状态（`trace_cal_frame_dbg` 的
  `lvl_max`/`noise`/`whiteish`/`black_thr`/`white_ref`/`state` + `s_fl_state`/`s_fl_lvl`/原始值/
  标定值/几何缓存 `trace_geom`），用来核对"柱高"和手算是否一致（`lvl = 128 ± (距离×s_rq)>>12`）、
  以及 `black_thr` 是不是就是越过阈值的路数。**自适应删掉后 `shift`/`shift_raw`/`jolt`/`ped`
  这四个字段恒 0**（结构体留着是给上位机看"确实没有自适应了"），也没有 `s_base*`/`s_shift*`/
  `s_dr` 了 —— 旧脚本还在读它们的话，读的是别的变量（改地址表见下一条）。
  （`pwsh -c "& 'C:\Program Files (x86)\SEGGER\JLink\JLink.exe' -CommanderScript out/_base_read.jlink"`）
- `out/_wiz.ps1 -Case pick|wait|retry|done|failed|noanalog [-SetN 0|1]`：**不按键、不采样、不写 nvram**，
  remotely 把标定向导/选套页的几种状态提示画到屏上再抓下来看（用于界面核验）。
  该文件头部注释记了 4 个 SWD 调试陷阱（别改 `uwTick`、软复位后首会话写失效、
  `kk_ui.current.page` 要独立会话写、想看"刚发生"的提示要先写时间戳再写 state）。
  **地址一律从 ELF 符号表现取（`nm` + `objdump`），绝不写死**：写死过一次
  （`$S_STATE = 0x20000ECC` 是上一版构建的值），字库/结构体一动就整体平移，
  脚本一直在写别的变量，屏上什么都不会变 —— 那次还把它误判成"固件里没画"。
  另外两个必须知道的点：**① 同名符号有多个**（`s_state` 就有两个，
  `s_state` 一个是 `nvram.c:85` 的保存状态 `0x20000CB8`、一个是 `trace_cal.c` 的向导状态 `0x20001035`），
  `trace_cal_state()` 读的是后者（用 `objdump -d --disassemble=trace_cal_state` 看它 `ldr` 的字面量）；
  **② halt 落在 OLED/I2C 传输中间会把提交打断**，之后主循环不再重画，抓到的是打断前那一帧。
- `out/_lcd.ps1` / `out/_lcd.py`：把 OLED 显存抓成 PNG（默认 180° 旋转，与肉眼所见一致）。
  `out/_lcd.ps1 [-Page N] [-Out out/_lcd.bin] [-Png out/_x.png]`（`-Page 2` = 设置页，
  页号见 `firmware/App/Inc/app_ui.h:21`）。**抓显存必须把两个面都抓下来**：`oled_buffers[2][1024]`
  （面 0 @ `0x20005FA8`、面 1 每构建都变，从 `nm` 取）是双缓冲，`oled_stable_index`/
  `oled_transfer_index` 只是"最近一次提交"的状态，halt 若正好落在 `kk_oled.c:95/:142` 那句
  `memset(oled_buffers[oled_draw_index], …)` 之后，下标指的那一面就是**刚被清空的**绘制缓冲区
  （实测 stable=0/pending=0 而面 0 全 0、内容在面 1），只按下标抓会得到"屏黑了"的假结论。
  现在的做法：**一个 J-Link 会话里 halt → savebin 两个面 → go**，主机侧按下标优先、空了就取另一面。
- **未决（已基本定性）**：「不稳!重按」这条提示串**没法用"halt + 读显存"远程取证**：
  它的窗口只有 1.5s（`HAL_GetTick() - s_retry_ms <= 1500`），而 J-Link 起一个会话就要 ~1.2s
  + settle 0.7s —— 默认参数下抓图时"已过 1787ms"，必然画不出来；把时间戳往前挪
  （`-TsBackMs -600`，抓图时已过 1236ms）后屏上仍是「全黑按中键」，说明取到的那帧是
  **窗口之前画的**（写完 state 的瞬间 age 为负 ⇒ hint=0，之后 halt 又把重画打断了）。
  也就是说：**这是采集方法的限制，不是固件问题**（字符串在 ELF 里、`draw_trace_page` 确实调
  `trace_cal_retry_hint()`、`objdump -d --disassemble=trace_cal_retry_hint` 的字面量
  `0x20001038`/`0x20001035` 与源码判据逐条对上）。属纯装饰提示，不影响功能；
  **要肉眼确认就在标定时故意手抖一下重按**，标题应变成「不稳!重按」。
