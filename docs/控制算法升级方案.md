# 控制算法升级方案（分段惯性导航 + 状态机改造）

> 面向当前工程：新板固件 `firmware/`，上层来自旧板 `Haixin/`。
> 本文回答"固定动作的车还能加什么算法"，并给出可直接落地的接口与顺序。
> 撰写依据：实际读过 `App/Svc/renwu.c`、`gyro_control.c`、`PID_tracing.c`、`tracing.c`、
> `App/Bsp/encoder.c`、`bsp_board.c`、`Core/Src/main_app.c`、`Core/Src/stm32g4xx_it.c`。

---

## 0. 先回答那个问题：要不要全局坐标系

**不要。** 理由不是"误差会大"这么笼统，而是具体的：

1. **JY61P 是 6 轴模块，yaw 是陀螺仪积分的，没有磁力计。** 它给的"绝对航向"
   本质就是"上电时刻起积分出来的相对量"，长时间必然漂（典型 1~5°/min，还随温度）。
   把它当世界坐标系用，等于把积分误差当基准。
2. **比赛时长 2~3 分钟，20~30 个动作段。** 全局 (x, y, θ) 靠积分推，误差随**时间**
   累积；而每段的增量误差只随**这段的时长**累积。
3. **全局坐标一旦错了没有纠正机会**；分段坐标每段都能被外部事件重新锚定。

所以正确形态是你说的那个：

> **每段一个局部原点（进入状态时锁存角度/里程）+ 段内用增量闭环 + 段与段之间靠外部事件重定位。**

段内增量是"闭环比绝对量准"的典型例子：转 90° 时比较的是 Δψ（几秒内的角度增量，
误差 < 1°），而不是"目标航向 82.3°，当前 81.1°"这种绝对量。

## 2. 目标架构：三层时间尺度

现在的代码只有第二层，而且是两个互斥分支；第一层是空的。

| 层 | 周期 | 职责 | 现状 |
|---|---|---|---|
| **L1 轮速环** | 1~5ms | 编码器 Δcount → 每轮 PI → PWM。把"给速度"变成"真速度" | ❌ 没有 |
| **L2 循迹/航向** | 5~10ms | 横偏差 → 转向；yaw → 航向保持/转向闭环 | ⚠️ 有，但互斥、无编码器、终止靠时间 |
| **L3 任务状态机** | 事件级 | 黑标事件 → 动作段推进 | ⚠️ 有，但全阻塞、有死分支 |

原则：**上层用状态量（角度/距离/事件），下层用时间量（ms）**。现在的错误是上层也在用时间量（HAL_Delay）。

## 3. 分段惯性导航：具体怎么做

### 3.1 段上下文（进入状态时锁存）

```c
typedef struct {
    uint32_t t0;              /* 段起始 tick，用于超时兜底 */
    float    yaw0;            /* 段起始航向（进入状态时锁存） */
    int32_t  cnt_l0, cnt_r0;  /* 段起始编码器计数 */
    /* 段内累积的局部位姿（只在这段内可信） */
    float    dpsi;            /* 相对 yaw0 转过的角度 deg */
    float    ds;              /* 相对 cnt0 走过的距离 m */
} seg_t;

static seg_t seg;
void  seg_begin(void);        /* 锁存 yaw0 / cnt0 / t0，清零 dpsi/ds */
void  seg_update(float dt);   /* 每 5ms：更新 dpsi、ds，积分局部 x/y */
```

### 3.2 关键换算（先实测轮径 D 再定）

JGB37-3865-520：11PPR × 4（正交）× 45（减速比）= **1980 计数 / 输出轴圈**。

```
k_dist = π·D / 1980          每计数前进的距离
D = 65mm → k_dist ≈ 0.1031 mm/count
D = 80mm → k_dist ≈ 0.1269 mm/count
```

**每 5ms 采样的分辨率问题（必须注意）**：空载 150RPM = 2.5 圈/s = 4950 count/s
→ 每 5ms 约 **25 个计数**，量化误差 ~4%，可用；但低速（占空比 20%）时只剩 ~5 个计数，
量化误差 20%。低速要么用 20ms 窗口 + 低通，要么用 M/T 法（测边沿间隔），别直接用 5ms 差分。

### 3.3 段的终止判据：从"时间到"改成"状态到"

| 现在（靠时间） | 改成（靠状态） | 备注 |
|---|---|---|
| `GyroControl_TurnLeft(90); HAL_Delay(700);` | `until fabsf(dpsi) >= 88 && fabsf(Gyro_Z) < 20` ，超时 1.5s 兜底 | 88° 不是 90°，留 2° 余量给过冲 |
| `Toggle_Gyro_Control(1,900,900); HAL_Delay(2000);` | `until ds >= 1.2f` ，超时 3s 兜底 | 直行距离 |
| `motor_tracing_pid(4.5); HAL_Delay(20);` ×N | 一个"循迹 N 毫秒/直到某事件"的步骤 | 见第 4.5 节 |

**每个状态量判据都必须带超时**：传感器可能失效，没有兜底就会永久卡死——这是现在阻塞式代码最危险的地方。

### 3.4 重锚机制（误差不跨段累积的真正原因）

不是"段短所以误差小"，而是**每段结束时被外部真值重新钉住**：

1. **循迹咬线**：只要有传感器压线，横向位置就有真值 → 把本段局部 y 归零
   （或对 yaw_target 做一次小修正）。
2. **黑标事件**：整排压线 = 赛道上的绝对标记 → 段计数归位、里程清零。
3. **零速修正（ZUPT）**：两个编码器都长时间为 0（车停着）时，yaw 不该变；
   实测变化量就是这一小段的漂移，直接减掉，并重新锁存 yaw0。
   这是分段方案天然的补充，几行代码。
4. **坡道结束**：pitch 回落到 0 附近 = 重新贴地，重新锁存。

## 4. 能加的算法（按 收益/工作量 排序）

### 4.1 编码器 + 轮速闭环 ★★★★★（其他一切的基础）

- 接线已焊好：**PB4/PB5 = TIM3_CH1/CH2（电机A）、PB6/PB7 = TIM4_CH1/CH2（电机B）**。
- 要做的：在 `bsp_board.c` 里加 `TIM3/TIM4` 的 `HAL_TIM_Encoder_Init` + `HAL_TIM_Encoder_Start`，
  每 5ms 读 Δcount（用 `(short)` 处理 16 位回绕），写进 `encoder.c`（现在是空的）。
- 收益：①"给速度"变"真速度"，跨电池电压一致；②所有"按距离"的判定成为可能；
  ③PWM 台阶造成的打滑可被检测。
- 注意：TIM4 在新板上是空的（`htim4` 只是 TIM7 的别名，别撞名），TIM3 也是空的。

### 4.2 转向用角速度做阻尼，别用 yaw 差分 ★★★★★

```c
/* 现在：derivative = (error - last_error)/dt，对 yaw 差分 → 噪声被放大 100 倍 */
/* 改成： */
pid->output = kp*error + ki*integral + kd*(-Gyro_Z);
```

JY61P 直接输出角速度（`jy61p.h:22` 的 `Gyro_Z`），**白送的阻尼量不用可惜**。
这是把"抖振的 D 项"换成"干净的物理量"，转向会立刻变干脆。

### 4.3 循迹 + 航向互补融合（线是绝对参考）★★★★★

不要"要么循迹要么陀螺"二选一（现在是互斥的），改成**同时跑、互相纠偏**：

- 线在时：横偏差 → 慢速修正航向目标
  `yaw_target += K_line * cross_error * dt`（K_line 取小，几秒量级修正）
  → 陀螺仪漂移被线拽回来。
- 线丢失时（过黑标/上坡/缝隙）：保持最后一帧航向 + 里程预测，**去预测线的位置**
  搜索，而不是原地乱转。

这比单纯"每段重置"更稳，因为它把两个传感器各自的强项用在各自的时间尺度上。

### 4.4 事件检测器（去抖 + 距离门限 + 计数）★★★★★

现在是"8 路全 SET 立即触发"，改成：

```c
/* 连续 3 次(15ms)整排压线 才算一次事件；两次事件间隔至少 X mm */
if (all_on_line(0xFF)) { hold++; } else { hold = 0; }
if (hold == 3 && seg.ds - last_event_ds >= MIN_GAP_MM) {
    marker_count++;                      /* 累加而不是赋固定值 */
    log_event(marker_count, seg.ds, seg.dpsi);
}
```

- 顺便记录 `black_run_mm`（整排压线持续的距离）：**用它区分"标记带 / 十字 / 斜坡前黑区"**，
  比 `black_num` 硬编码的先后顺序鲁棒得多。
- `black_num` 那种"赋魔数 + 精确匹配"的写法（漏一拍就整串错位）应该换成
  **计数 + 每状态一次触发门闩**，并且加断言：进了一个没有对应分支的值就报警而不是静默卡死。

### 4.5 非阻塞步骤框架（替掉 210 个 HAL_Delay）★★★★★

```c
typedef struct {
    const char *name;
    void (*enter)(void);
    bool (*update)(float dt);   /* 返回 true = 本步完成 */
    uint16_t timeout_ms;        /* 兜底，必须填 */
} step_t;
```

一段动作 = 一个 step 数组（比如"左转90°→直行1.2m→抬舵机→再左转90°"）。
收益是立竿见影的：
1. 转弯判据能写成角度（第 3.3 节）；
2. 每步自带超时和**失败重试**（现在卡住就是永远卡住）；
3. **UI 能显示"当前第几步"**——现场调试价值极大；
4. 每步 enter/exit 打一行 RTT 日志 → 直接得到一份状态迁移时间线。

### 4.6 黑匣子 + 运行日志 ★★★★★（比赛现场最值钱）

- 100Hz 环形缓冲，每条：tick、yaw、Δcount×2、8 路循迹原始位、当前 step id、两路 PWM、
  INA226 电压/电流、舵机位置。
- 跑完经 RTT 或无线串口（LPUART1 → U12 调试座）导出 CSV，电脑上画图。
- **软复位不清 SRAM**（`.noinit` 段 + magic word）→ 复位后还能拿到"出事前最后 10 秒"。
- 现在的投入很小：DWT 打点和 RTT 已经在跑了（`main_app.c` 每秒打 `FRAME:`）。
- 有了它，"为什么第 3 次跑失败"从猜变成看图。

### 4.7 INA226 别只用来显示电压 ★★★★

- **卡死/顶墙检测**：电流突增 + 里程不增 → 判定被顶住 → 自动"后退 15cm 重试"。
  比赛里这是典型能救回一次跑的机制。
- **电压前馈**：12.6V 掉到 10.5V 时同样 PWM 转速差 ~20%，
  用 `Vnom/Vbat` 补偿到轮速环目标上，整场比赛行为才一致。
- **全程能量/功率曲线**：能看出某个动作是不是在硬顶（机械问题）。

### 4.8 加速度斜坡（T 型/S 型）★★★★

现在 `Load(900,900)` 是阶跃 → 轮子打滑 → **里程和航向一起失真**（打滑时编码器还在转，
但车没走那么远，比"没信号"更坏）。加受限于加速度的斜坡，几行代码，
对里程精度和过坡稳定性都是直接收益。

### 4.9 打滑检测（顺带白送）★★★

`ω_enc = (v_r - v_l) / L`（L = 轮距），和 `Gyro_Z` 比：
`ratio = Gyro_Z / ω_enc`。正常接近 1；明显偏离说明有轮子在打滑/空转。
可以拿它做坡道检测、地面判据，或者只是记进黑匣子当诊断量。

### 4.10 姿态（Roll/Pitch）★★★

- 坡道检测：pitch 超阈值 → 进"爬坡模式"（转向增益调小、力矩加大、
  循迹因为线可能看不见而临时以航向为主）。
- 防翻/托底保护：roll/pitch 超限立即停——比任何算法都重要的一次保护。

### 4.11 无线串口实时调参 ★★★★

UART4/LPUART1 已经引到调试座。加一个极简参数协议（`Kp=...\n`）：
**不用重新烧录就能调 PID**，对现场调参是数量级的效率差别。
现在参数都是 `#define`（`gyro_control.c:16-18`）。

### 4.12 失败恢复与全局 watchdog ★★★★

- 每步超时 → 恢复步：后退 + 重新找线 + 重试一次。
- 全局：超过 T 秒没有任何标记事件 → 进"找线模式"。
- 现在任何一步卡住就永远卡住，而且是在 `HAL_Delay` 里卡住。

## 5. 顺手该修的 5 个问题

1. `gyro_control.c:239-250`：`TurnLeftFixed/TurnRightFixed` 名实相反，且注释"10度"实为 90°。
2. `gyro_control.c:169`：`dt = 0.01f` 与 `BSP_GYRO_PERIOD_MS = 5` 不符 → I/D 增益差 2 倍。
3. `gyro_control.c:115-138`："锁存 yaw0"依赖 `GyroControl_Init()` 清标志这个**隐蔽耦合**
   （`Toggle_Gyro_Control` 每次 enable 都调 Init 才碰巧对）。应显式化成
   `GyroControl_LatchHeading()`，否则将来一改就错。
4. `renwu.c`：死分支 8/12/14/20/22 → 要么补上触发条件、要么删掉，别留着当"调过的代码"。
5. 循迹极性统一：`tracing.c`（取反）和 `PID_tracing.c`（原值）两套 → 只留一套并统一命名。

1. TIM3/TIM4 编码器模式 + 每 5ms 读 Δcount（`encoder.c` 现在是空的）。
2. 补 `HAL_TIM_PeriodElapsedCallback`：`htim6 → motor_tracing_pid_0_task()`、

**P2（鲁棒性）**
7. 黑匣子日志 + RTT/无线导出。
8. INA226 卡死检测 + 电压前馈；加减速斜坡。

**P3（优化）**
9. 循迹-航向互补融合；坡道模式；打滑检测；失败重试策略；无线实时调参。

## 7. 一句话总结

> 惯性导航在这个车上**不该做全局坐标系**，而应该做成
> **"每段锁存一次航向/里程原点 + 段内用增量闭环 + 每段靠黑标/咬线重新锚定"**；
> 真正带来提升的不是这套积分本身，而是它背后的三件事：
> **转弯按角度收尾（而不是按时间）、有编码器做速度闭环、状态机不阻塞**。
