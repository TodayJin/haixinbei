# 上位机通信协议 v1（PC <-> 主控）

> 配套实现：`tools/console/`（新上位机：Python 桥 + React 前端，`--sim` 可直接跑仿真；
> HTTP/SSE 契约见 `tools/console/docs/API.md`）。旧 Qt 上位机 `tools/host/` 已删除，
> 需要它时从 git 提交 `5051a4d` 取回。
> 固件侧**已实现**（`App/Svc/host_link.c` + `board.c` 的 LPUART1）；本文第 8 节是最初的 C 参考实现与对接清单，保留作对照。
> 物理链路：**LPUART1（PC1 = TX / PC0 = RX）→ U12 调试座 → 无线下载器的虚拟串口**。

---

## 1. 为什么是二进制而不是文本

之前调参靠改 `#define` 重新烧录（例如 `gyro_control.c:16-18`）。
改成二进制定长帧的理由：

| | 二进制定长 | ASCII 文本 |
|---|---|---|
| 100Hz × 64 字节遥测 | **约 7.4 KB/s（230400 的 32%、921600 的 8%）** | 同内容约 3~5 倍，还难解析 |
| 丢一个字节 | CRC 拦住，最多丢一帧，自动重同步 | 整行错乱，要靠找换行符 |
| MCU 侧开销 | 一次 memcpy + 查表 CRC | printf 格式化，既慢又占 Flash |

## 2. 帧格式

全部 **小端（little-endian）**。

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | SOF | 固定 `A5 5A` |
| 2 | 1 | type | 帧类型，见第 4 节 |
| 3 | 1 | seq | 序号。PC 下发时由 PC 分配，MCU 在 ACK 里**原样回抄** |
| 4 | 1 | len | payload 长度，0..128 |
| 5 | len | payload | 载荷 |
| 5+len | 2 | crc16 | CRC16/CCITT-FALSE，覆盖 `type|seq|len|payload` |

固定开销 **7 字节**。

### 重同步规则

接收方按字节流扫描：找到 `A5 5A` 后校验 len 与 CRC。
**CRC 失败时只前移 1 字节重新找帧头**，所以上电、插拔、电磁干扰造成的乱码能自愈，
不需要人工重连。代价是最坏情况下多扫几十字节。

## 3. CRC16/CCITT-FALSE

参数：poly = `0x1021`，init = `0xFFFF`，输入不反转，输出不异或。

**标准校验值：`"123456789"` → `0x29B1`**（上位机单测里用它做锚点，固件实现必须一致）。

~~~c
/* 查表版，256 项表可以由上位机 tools/host/protocol.py 生成 */
uint16_t crc16_ccitt(const uint8_t *d, uint16_t n)
{
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= (uint16_t)(*d++) << 8;
        for (int i = 0; i < 8; i++)
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021)
                                 : (uint16_t)(crc << 1);
    }
    return crc;
}
~~~

## 4. 帧类型

| 值 | 名称 | 方向 | 载荷 |
|---|---|---|---|
| 0x01 | TELEM | MCU → PC | 定长 32，见第 5 节 |
| 0x02 | POSE | MCU → PC | 定长 12，**赛道位姿与得分**，见第 5.2 节 |
| 0x30 | LOG | MCU → PC | 黑匣子记录（同遥测，MCU 侧自行追加字段） |
| 0x10 | PARAM_GET | PC → MCU | `id`(u16)，`0xFFFF` = 全部 |
| 0x11 | PARAM_SET | PC → MCU | `id`(u16) + `value`(f32) |
| 0x12 | PARAM_REPORT | MCU → PC | `id`(u16) + `value`(f32) |
| 0x13 | PARAM_SAVE | PC → MCU | 空（参数写 Flash） |
| 0x20 | CMD | PC → MCU | `cmd`(u8) + `arg`(i32) |
| 0x21 | ACK | MCU → PC | `seq_req`(u8) + `status`(u8) |
| 0x40 | HELLO | MCU → PC | 见第 7 节 |
| 0x41 | HELLO_REQ | PC → MCU | 空 |
| 0x50 | TEXT | MCU → PC | 调试文本，UTF-8（兼容 GBK） |
| 0x60 | TASK_LIST | PC → MCU | 空（要一份车上任务目录） |
| 0x61 | TASK_LIST_R | MCU → PC | 一条任务一帧：`id`(u16) + `len`(u16) + `crc`(u16) + `flags`(u8) + `name_len`(u8) + 名字；**目录发完再发一帧空载荷收尾** |
| 0x62 | TASK_PUT | PC → MCU | `id`(u16) + `off`(u16) + 数据（≤ **124**，帧载荷上限 128 − 4） |
| 0x63 | TASK_COMMIT | PC → MCU | `id`(u16) + `len`(u16) + `crc`(u16) + `flags`(u8)，可选再跟 `name_len`(u8) + 名字；`flags` 是**保留位**（车上原样存进目录页、不解释任何位；bit0 曾经是「开机自启」，2026-10-04 按用户 m24999 要求整个删掉） |
| 0x64 | TASK_GET | PC → MCU | `id`(u16) + `off`(u16)（要回读整镜像；分帧回） |
| 0x65 | TASK_DATA | MCU → PC | `id`(u16) + `off`(u16) + 数据（同名分帧，末帧由 `len < 124` 判完） |
| 0x66 | TASK_DEL | PC → MCU | `id`(u16) |
| 0x67 | TASK_RUN | PC → MCU | `id`(u16) |
| 0x68 | TASK_STOP | PC → MCU | 空 |
| 0x69 | TASK_STATUS | MCU → PC | `id`(u16) + `state`(u8) + `running`(u8) + `block`(u16) + `elapsed_ms`(u32) + `flags`(u8)（**11 字节**） |

任务帧（`0x60`–`0x69`）的完整语义 —— 包括二进制镜像格式、各状态码、分帧与 `renwu_flag`
（车在动就拒写）的口径 —— 见仓根 [`docs/任务编程.md`](任务编程.md)；两张表必须一致，改一边就要改另一边。
`TASK_STATUS` 内容一变就推、没变时 1Hz 心跳（**`elapsed_ms` 不算"变"**：它每毫秒都变，算进去会退化成每拍一帧、吃满串口带宽；见 [`docs/任务编程.md`](任务编程.md) 的 `T_TASK_STATUS` 行）；未载入任何程序时 `id = 0xFFFF`、`state = 0xFF`、`running = 0`。

**ACK 的 `seq_req` 必须回抄请求帧的 seq**，上位机靠它把"应答"和"哪次操作"对上。

**`CMD` 的载荷必须发满 5 字节**（`cmd` u8 + `arg` i32 小端）：固件读 `arg` 的条件是
`len >= 5`（`firmware/App/Svc/host_link.c:776-790`），载荷短了 `arg` 恒为 **0** ——
早期上位机只发 `cmd + arg低字节` 两字节，「设置遥测频率」于是被固件的 `arg<1 → 1` 钳成
**1Hz**（2026-10-04 真车实测：发出 50 却从 75 帧/s 掉到 1 帧/s，CRC/重同步/丢帧全 0，
纯是固件在按 1Hz 发）。现在固件额外接受 `len >= 2` 的老式帧并取**低字节**（当无符号值用），
只为兼容老镜像；新上位机一律发满 4 字节（`bridge/protocol.py` 的 `cmd_payload()`）。
上位机每个下行帧都记账，收到非 0 状态会在日志里标红。

### ACK 状态码

| 值 | 含义 |
|---|---|
| 0x00 | OK |
| 0x01 | CRC 错 |
| 0x02 | 未知帧类型 |
| 0x03 | 参数 id 不存在 |
| 0x04 | 参数超范围 |
| 0x05 | 未就绪 |
| 0x06 | 未知命令 |
| 0x07 | 忙（比如任务正在跑） |
| 0x08 | **不支持**（已废弃的命令/功能；见下面的 `0x02..0x04`） |

### 命令码

| 值 | 命令 | arg |
|---|---|---|
| 0x01 | 停止 | 0 |
| 0x02 / 0x03 / 0x04 | ~~启动任务 A / B / C~~ **已废弃** | 0 |
| 0x05 | 陀螺仪零偏校准 | 0 |
| 0x06 | 参数写 Flash | 0 |
| 0x07 | 清除故障 | 0 |
| 0x08 | 设置遥测频率 | Hz，**固件钳在 1..200**（`arg<1 → 1`、`arg>200 → 200`）（`host_link.c:800-803`） |
| 0x09 | 软复位 | 0 |
| 0x0A | 开始/停止车上记录（黑匣子） | 1 / 0 |

> **`0x02/0x03/0x04` 已废弃**：车上固件里的内置比赛流程（旧 `renwu.c` 的 A/B/C）已经删除，
> 收到这三个命令一律回 **`0x08` 不支持** + 一条 `[fw] 内置任务流程已移除：请用任务页（0x67 RUN）…` 文本。
> 上位机不要再提供「启动任务 A/B/C」按钮（`#/control` 页已删掉）；任务改走 `0x60`–`0x69`
> （`docs/任务编程.md`）—— 拼装、烧写、启停都在 `#/tasks` 页。字节定义保留是为了让老客户端拿到
> 明确的「不支持」而不是「未知命令」。
> `0x01` 停止现在也**会停住正在跑的任务**（等价于 `0x68 T_TASK_STOP` + 停车）。

| 6 | i16 | pitch_x10 | 0.1° | |
| 8 | i16 | roll_x10 | 0.1° | |
| 10 | i16 | v_l_mmps | mm/s | 左轮速度（**编码器算出来的**，不是 PWM） |
| 12 | i16 | v_r_mmps | mm/s | 右轮速度 |
| 14 | i16 | pwm_l | −7200..7200 | 左电机实际输出 |
| 16 | i16 | pwm_r | −7200..7200 | 右电机实际输出 |
| 18 | u16 | vbat_mv | mV | INA226 母线电压 |

| 24 | u16 | servo2_us | us | 舵机 2 脉宽 |
| 26 | u8 | line_mask | — | **bit i = 第 i+1 路灰度压线（1 = 压线）** |
| 27 | u8 | state_id | — | **任务解释器在跑时的当前状态号**（`TaskRun_State`）；没在跑（含没载入）= `0xFF` |
| 28 | u16 | loop_us | us | 主循环单帧耗时（已有 DWT 打点） |
| 30 | u8 | flags | — | 见下 |
| 31 | u8 | reserved | — | 补位，必须发 0 |

### flags 位

| 位 | 含义 |
|---|---|
| bit0 | 陀螺数据有效 |
| bit1 | 循迹丢线 |
| bit2 | 疑似卡死（电流大 + 里程不走） |
| bit3 | 坡道中 |
| bit4 | 故障 |
| bit5 | 车上黑匣子正在记录 |

> **line_mask 极性约定（重要）**：协议里 **1 = 压线**。
> 但工程里现在有两套相反的含义 —— `tracing.c:9-16` 取反、`PID_tracing.c:18-25` 用原值。
> **固件必须在打包遥测时归一化成"1 = 压线"**，否则上位机的灰度阵列会整排反相。

## 5.2 位姿与得分帧（POSE，定长 12 字节）

给上位机的**赛道俯视图**用：画小车在地图上的位置、朝向、轨迹，以及障碍完成情况与得分。

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u16 | x_dmm | 0.1cm，0..4500（场地左上角为原点，x 向右） |
| 2 | u16 | y_dmm | 0.1cm，0..4500（y 向下，与官方俯视图同向） |
| 4 | i16 | yaw_x10 | 0.1°，0 = +x，顺时针为正 |
| 6 | u8 | obstacle_id | 当前所处的障碍编号（0 = 不在障碍里） |
| 7 | u8 | flags | 见下 |
| 8 | u16 | score | 已获得的障碍分（不含计时分） |
| 10 | u16 | done_mask | bit i 表示第 i+1 号障碍已完成 |

### POSE flags 位

| 位 | 含义 |
|---|---|
| bit0 | 正处在某个障碍内 |
| bit1 | 刚完成一个障碍 |
| bit2 | 被挡住（例如车太高钻不过 20cm 隧道） |
| bit3 | 疑似打滑 |
| bit4 | 已跑完一轮 |

> **真车上这个位姿是推算出来的**（编码器里程 + 陀螺），没有全局坐标系，会漂。
> 仿真里是真实值。上位机的价值在于**把状态可视化**，不在于精确到厘米。
> 若暂不做位姿推算，这一帧可以不发（上位机自动不画车）。

## 7. HELLO 帧

payload **24 字节**（v2 在末尾补了 u32 能力位）：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u16 | 固件版本 |
| 2 | u8 | 协议版本（当前 2） |
| 3 | u8 | 保留，发 0 |
| 4 | u16 | param_crc |
| 6 | u16 | 当前遥测频率 Hz |
| 8 | char[12] | 板名，UTF-8，不足补 0 |
| 20 | u32 | **能力位**（v2 新增）：bit0 TELEM2 / bit1 ACTIONS / bit2 SERVO / bit3 DRIVE / bit4 CAL / bit5 FLASH / bit6 WATCHDOG / **bit7 TASK** |

**上位机不许靠版本号猜功能** —— 页面按能力位决定显示什么：位=0 的模块显示成"固件不支持"而不是报错
（`#/tasks` 页就是靠 bit7 决定要不要显示琥珀色提示）。bit7 = 任务程序（`0x60`–`0x69` 帧 + 车上 Flash
任务存储），实现口径见 [`docs/任务编程.md`](任务编程.md)。能力位的枚举与 `tools/console/docs/API.md`、
`firmware/App/Svc/host_link.h`（`HOST_CAP_*`）必须三处一致。

编译结果：Flash **45%**（text 58008 + data 128 / 128KB），RAM 10%（bss 12488）。唯一告警是既有的 RWX LOAD segment。

> **AF8 是查数据手册确认的**（DS12288 Rev6 第 75 页 Table 13：PC0→AF8=LPUART1_RX，PC1→AF8=LPUART1_TX），不是靠记忆。

**遥测里的都是真实读数**：yaw/pitch/roll 来自 JY61P；`pwm_l/pwm_r` 读 **TIM8 CH1..4 的 CCR**（AT8236 两根输入的实际值）；舵机脉宽读 TIM1 CCR；电压电流读 INA226（**只在 `OLED_IsBusy()==0` 时读**，否则会和异步刷屏抢 I2C1）；`line_mask` 取 8 路灰度原始电平（1 = 压线）；`state_id` 取任务解释器**在跑时**的当前状态号（`TaskRun_State`，跑完 END / 被 STOP 之后 = `0xFF`；同一口径也用在 `TELEM2[51]` 的 `task_id` 上，`0x69` 状态帧则额外单独报 `running`）。

**未实现就明确回「未就绪」的地方**（不假装成功，否则上位机以为生效了）：

| 项 | 行为 |
|---|---|
| `PARAM_SAVE`（写 Flash） | 回 `ST_NOT_READY` + 一条 TEXT 说明。参数目前只在 RAM，**掉电丢** |
| `CMD_CALIB_GYRO` / `CMD_SAVE_PARAMS` / `CMD_SET_LOGGING` | 回 `ST_NOT_READY` |
| 遥测 `v_l_mmps` / `v_r_mmps` | **2026-10-05 起为真实编码器轮速**（TIM3/TIM4，`SpeedControl_SpeedMmps()`，mm/s，正 = 前进）。此前长期恒为 0，把操控页的速度波形变成一条假 0 线（用户 m28949 因此误判"PID 把速度抵消成 0"） |
| flags 的 bit0（陀螺有效）/ bit5（车上记录） | 不发，不倒手为「正常」 |

### 8.2 组帧与发送

~~~c
#define HOST_SOF0 0xA5
#define HOST_SOF1 0x5A

static uint8_t tx[7 + 32];

/* 组一帧并直接从 LPUART1 发出；len = payload 长度 */
void host_send(uint8_t type, uint8_t seq, const uint8_t *payload, uint8_t len)
{
    tx[0] = HOST_SOF0; tx[1] = HOST_SOF1;
    tx[2] = type; tx[3] = seq; tx[4] = len;
    if (len) memcpy(&tx[5], payload, len);
    uint16_t crc = crc16_ccitt(&tx[2], (uint16_t)(3 + len));
    tx[5 + len] = (uint8_t)(crc & 0xFF);
    tx[6 + len] = (uint8_t)(crc >> 8);
    HAL_UART_Transmit(board_dl_handle(), tx, (uint16_t)(7 + len), 20);
}
~~~

> 上面这段是**早期**的写法（阻塞 `HAL_UART_Transmit` + 512B 收环形缓冲），只留作帧格式参考。
> 2026-10 提速后实机是：**收 = DMA1_Ch2 循环搬运 2048B（主循环按 CNDTR 取）**，
> **发 = DMA1_Ch3 槽位队列（8 × 144B，`board_dl_send()` 只拷贝、满了丢帧并计数）**，
> 两者都在 `firmware/Core/Src/board.c`。LPUART1 = **230400 8N1**（`board.c` 的 `DL_BAUD` 就是
> 230400，桥与网页的默认值也是它），遥测默认 **100Hz**（约 32% 带宽），
> 所以主循环再也不用等串口。改速率时桥/网页那一侧必须一起改（`--baud`）。
>
> **为什么是 230400 而不是更快的 921600**（2026-10-04 定）：车上这颗 J-Link 的 CDC VCOM
> （`JLink CDC UART Port (COM26)`）上限只有 **230400** —— 对它试 ≥460800 会让探针崩溃并枚举成
> `PID_0101` 引导态（须物理拔插恢复），所以把 `firmware/Core/Src/board.c` 的 `DL_BAUD` 降成
> 230400 烧进去、桥用 `--baud 230400` 起。**要真正跑 921600 得换普通 USB-TTL 接 U12**
> （`固件接口规格.md:259`），并把 `DL_BAUD` 与桥的 `--baud` 一起改回 921600。
> 230400 下的实测：遥测 100Hz → 实收 **100.0 帧/s**（0 CRC 错 / 0 重同步 / 0 丢帧计数）、
> SSE 36.8 事件/s 72 KB/s、桥 CPU 14.8%；把遥测频率调到 **200Hz** 也稳（201.4 帧/s ≈ 14.2 KB/s，
> 230400 的 62%），`/api/link` 的 `rtt_ms` 11.9ms（100Hz）/ 7.3ms（200Hz）。

### 8.3 收帧状态机（要点）

1. 找 `A5 5A`；2. 收 type/seq/len；3. `len > 128` 就丢弃并前移 1 字节；
4. 收满 `len+2` 字节校验 CRC；5. **CRC 失败前移 1 字节重同步**；6. 分发处理。

处理函数至少覆盖：`HELLO_REQ`→回 HELLO；`PARAM_GET`→回 PARAM_REPORT；
`PARAM_SET`→范围检查后写入并回 ACK + PARAM_REPORT；`PARAM_SAVE`→写 Flash；
`CMD`→执行并回 ACK。**未知类型也要回 ACK(0x02)**，否则上位机无从判断。

### 8.5 验证顺序（不需要整车）

1. 只初始化 LPUART1 + 每秒发一帧 TEXT，上位机连上应能看到文本 —— 先证明链路通。
2. 发 TELEM，看波形有没有动、CRC 错计数是否为 0。
3. 读参数（PARAM_GET）→ 全部回读成功且 param_crc 与上位机一致。
4. 改一个参数 → 车上变量真的变了（用 RTT 打印对照）。
5. 最后才接任务状态机。

## 9. 兼容性

- `len` 上限 128，接收方必须拒绝超长。
- 遥测帧**定长 32 字节**，以后加字段请开新 type（如 0x02），不要改 0x01 的长度，
  否则新旧上位机会错位。若要扩展，走 `reserved` 字节或新 type。
- 协议版本在 HELLO 里，上位机发现不匹配会提示。

## 10. 硬件到位后怎么验证（按顺序，别跳步）

前提：板子通过 **U12**（1=3V3、4=GND、5=网名 LPUART1_RX=**PC1 车发**、6=网名 LPUART1_TX=**PC0 车收**，见 `固件接口规格.md` §3.6 与注1）接无线下载器；或直接接 **USB-TTL**，注意交叉：适配器 TX → 板子 PC0(RX) = **U12 脚6**，适配器 RX → 板子 PC1(TX) = **U12 脚5**，GND → U12 脚4。

1. **先看有没有在发**：通电后 RTT 应打印 `host link init OK`，随后每秒一行 `HOST: rx=0 tx=N crc=0 ... txdrop=0 rxover=0`，**tx 每 +1 ≈ 每秒 100 帧**（默认 100Hz 遥测，`CMD_SET_TELEM_HZ` 可改，固件钳 1..200）。tx 在涨 = LPUART1 发送通路通；rx 不动是正常的（上位机还没连）。`txdrop`/`rxover` 只要不是 0 就说明发队列/收缓冲溢出，先降遥测频率。
2. **连上位机**：`run_host.bat` → 模式选**串口** → 选下载器的 COM 口 → **波特率跟着固件的 `DL_BAUD` 填**（现在两边默认都是 **230400**；用 J-Link 的 VCOM 时也只能 230400，见 §8.2 的注）→ 连接。日志里应出现 `握手成功：quandi-car，固件 v1，遥测 100Hz`，且**参数表指纹一致**。
3. **看波形动**：波形页应看到 yaw / PWM / 电压电流在动。**轮速恒为 0 是预期**（编码器未做）。
4. **读参数**：参数页点「从车读取」→ 23 项应全部回读成功。
5. **改参数看回读**：把循迹 Kp 改一下 → 回读值变化，RTT 里 `sets=N` 会 +1。
6. **最后**才接任务状态机。

> ⚠ 到第 5 步为止，参数改了也只是进了固件 RAM，**控制律仍用代码里的常数** ——要真正生效得把 `pid.c`/`gyro_control.c` 里的 `#define` 换成 `host_param_get()`（§8.4，**尚未做**）。这是目前最大的一处「看着能用、其实没接线」的地方，下一步就做它。
