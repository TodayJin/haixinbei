# 旧码（Haixin/，STM32F103VET6）→ 新板（G474RBT6）移植对照

> 目的：用户要求「把之前所有算法、任务的流程之类的东西都和现在同步」。这份文档是**逐模块对照表 + 同步状态**，
> 既记录已经同步的部分（含为什么是等价改写），也记录**刻意没动**和**仍需确认**的部分。
>
> 判据（本轮怎么算"同步"）：① 函数集是旧码的超集（旧码里每个对外函数在新码里都有对应实现）；
> ② 算法主体逐行等价（注释/空白/引脚宏之外没有逻辑差异）；③ 数值刻度换算到新板量纲；
> ④ 旧板靠定时器中断跑的周期任务，在新板有等价的调用点；⑤ 旧板主循环里的调用（含条件与停机逻辑）在新板有等价实现。
>
> 生成方法：`out/port_audit.mjs`（逐对模块列函数名与数字字面量，报「旧有新无」）、
> `out/port_diff.py`（去注释/去字符串/压空白后 difflib 比较）、`out/servo_table_cmp.py`（舵机动作表事件流比较），
> 加上人工阅读旧 `Haixin/Core/Src/main.c`、`tim.c` 与新 `firmware/Core/Src/main_app.c`、`firmware/App/Bsp/bsp_board.c`。

## 2. 逐模块细节

### 2.1 电机 `motor.c`
对外 API 全同名同义：`abs()` / `Motor_Init()` / `Load(moto1, moto2)` / `Limit()` / `Set_Pwm(mode, l, r)`（mode 1..5 = 前/后/左转/右转/停）。
差异只在底层：
- 旧板每个电机「1 路 PWM + 2 个方向 GPIO」；新板 AT8236 每电机两根输入都是 PWM（TIM8_CH1–CH4），`Load()` 里按符号决定哪根出 PWM。
- 新 `Load()` 内部先 `Limit()`（旧 `Load()` 不夹，只有一个独立的 `Limit()` 函数没人保证调用）。
- 新 `Load()` 有 **右路镜像补偿** `int b = -moto2;`：台架实测两电机镜像安装，同一电气极性下物理转向相反；配套的编码器侧翻转在 `firmware/App/Bsp/encoder.c`（左路取负），两处必须一起改（`motor.c:29-36` 有完整标定记录）。

### 2.2 编码器 `encoder.c`
旧文件只剩 `extern`，正文（读 TIM 计数器的代码）整段被注释掉 —— **旧板比赛时没有用编码器闭环**。
新板 `Encoder_Init()/Encoder_Reset()/Encoder_ReadDelta(htim)`，TIM3 = 电机 A、TIM4 = 电机 B（`htim4_enc`，因为 `htim4` 这个名字在本工程已经是 TIM7 的别名）。

### 2.3 舵机 `servo.c`
- `Servo_Control(x, angle)` 兼容层保留：`pulse = 500 + 2000*angle/180`（µs），与旧板公式相同；两个板子的 TIM1 都是 **1µs 刻度 / 20ms 周期（50Hz）**，所以脉宽数值可直接沿用。
- `Servo_Move(x)` 的 14 个比赛动作预设 **逐个角度、逐个延时都比对过，完全相同**（`out/servo_table_cmp.py`），例：case5 = (1,135)(2,170) 延 400ms (1,90) 延 100ms (1,80)。
- 通道映射变了：旧板 x=1→TIM1_CH4、x=2→TIM1_CH3；新板 x=1→CH1、x=2→CH2（`firmware/App/Bsp/bsp_board.h:31` 有说明）。装车后要确认两个舵机的插头确实在 PA8/PA9 上，否则动作会打反。
- 新增非阻塞缓动层 `Servo_SetPulse/Servo_SetDeviation/Servo_SetAngleDev/Servo_SetAngle/Servo_MoveTo/Servo_Task`（旧板没有）。`Servo_Move()` 仍走立即写脉宽，不依赖 `Servo_Task()`。

### 2.4 按键 / 蜂鸣器
- `key.c`：去注释与引脚宏替换后 diff ratio 0.916，逻辑完全一致（三个键、低有效）。旧板在主循环里轮询 `key()` 自己分派；新板键值交给 `kk_ui`（消抖、长按、连发，见 `firmware/Middlewares/kk_ui`）。
- `buzzer.c`：只有引脚宏差异。

### 2.5 RGB
旧板 `rgb.c` 有实现（6 个函数）；新板 `firmware/App/Bsp/rgb.c` 6 个函数全是空壳 —— **新板没有 RGB 灯，这是有意为之**，不是漏移植。

### 2.6 循迹输入 `tracing.c`
- 旧版 `read_tracing_data()` 直接 `HAL_GPIO_ReadPin()` 读 8 路数字口，**并且在里面用 OLED 画 8 个数字**。
- 新版：`trace_read_channel(idx)` 先取模拟量（`trace_cal_channel()`，8 路灰度经 I2C/串口标定后的阈值判定），拿不到（没标定/没模块）才回落 `bsp_trace_bit(idx)` 数字口；另有 `trace_invert` 取反开关与 `trace_on_line_count()`。画屏整段删掉（屏由 kk_ui 负责）。
- `trace_cal_channel()` 只读缓存 `trace_cal_raw[]`（`firmware/App/Svc/trace_cal.c:372-382`，缓存由主循环的 `trace_cal_poll()` 刷新），**不做 I2C 阻塞读** ⇒ 可以在定时器中断里调用（这是把循迹环放进 TIM6 中断的前提）。
- 灰度标定（黑/白两点、阈值、质量判定）**怎么标、怎么在屏上和上位机上检验**，另见 [灰度标定与检验](灰度标定与检验.md)。

### 2.7 循迹控制 `PID_tracing.c`
- 旧码 7 个函数在新码里全有；新码另有 `motor_tracing_cascade()`（误差 → 目标航向 → 角度环串级）、`motor_tracing_reset_cascade()`、`apply_speeds()`（速度环开着就下目标，否则直出 PWM）、`show_tracing_data_pid()`（空实现，交给 kk_ui）。
- **本轮同步**：旧接口 `motor_tracing_pid()` / `motor_tracing_pid_0()` / `motor_tracing_pid_0_task()` 里写死的基准速度 `1000` / `200`（旧板刻度，等于 100% / 20% 占空比）改成读参数 `HP_BASE_SPEED`（默认 6480）/ `HP_BASE_SPEED_SLOW`（默认 2500），见 §3。
- **本轮同步**：`PID_Tracing_Timer_Start/Stop` 原本调用 `HAL_TIM_Base_Start_IT(&htim2)` / `Stop_IT` —— `htim2` 在本工程是 **TIM6 的别名**，也就是说任务流程里 `PID_Tracing_Timer_Start(); HAL_Delay(1000); PID_Tracing_Timer_Stop();` 会把整个 5ms 运动节拍停掉，而"后台循迹"其实压根没跑（旧板是 TIM2 10Hz 中断里跑 `motor_tracing_pid_0_task()`）。现在改成软件开关 + 100ms 分频（`PID_TRACE_BG_DIV 20`，5ms × 20 = 100ms = 10Hz），由 `Motion_Task()` 每拍驱动。
  - 为什么必须分频：旧板 10Hz 调好的 PID，若按 200Hz 跑，`err - last_err`（D 项）会强 20 倍、积分累加（I 项）会弱 20 倍。

### 2.8 角度环 `gyro_control.c`
- 旧码 15 个函数在新码里全有（超集）：参数走 `host_param_get(HP_GYRO_KP/KI/KD/ILIMIT, …)`，`GYRO_DT 0.005f`，多了 `GyroControl_IsEnabled/SetTargetAngle/GetTargetAngle/SetBaseSpeed`，速度环开着就下目标、否则 `Load()`。
- **本轮同步**：`Gyro_Timer_Start/Stop` 原本操作 `htim4` = **TIM7 的别名**（会停掉 `Servo_Task()` 舵机缓动），旧板这两个函数开关的是 TIM4 角度环中断。现在改成空实现：两个周期 tick 由 `bsp_periodic_start()` 在初始化里启动，角度环由 `Motion_Task()` 在 TIM6 上以 5ms 调用。

### 2.9 比赛任务 `renwu.c`
- **逐行照抄**：`out/port_diff.py` 与逐行比对显示，旧 `Haixin/Hardware/renwu.c` 与新 `firmware/App/Svc/renwu.c` 只差 include 行（旧 `usart.h`/`OLED.h` → 新 `rgb.h`）。所以流程本身（`A()` 的 `black_num` 状态机、各段 `Load`、`HAL_Delay`、`Servo_Move`、`Buzzer_blink`）不用重写，**要同步的只有数值刻度和调用点**。
- 结构：`renwu()` 按 `renwu_flag`（0 停 / 1 A / 2 B / 3 C）分派；`A()` 是主流程（含几十段 `motor_tracing_pid(4.5); HAL_Delay(20);` 的循迹段与 `Toggle_Gyro_Control()` 直行段）；`B()`/`C()` 是空壳（旧码也是空壳）。
- **本轮同步 ①（刻度）**：45 处旧板刻度数值包成 `RW(v) = task_pwm(v) = v * HP_TASK_SPEED / 900`（默认 6480 = 7200 的 90%），`Load(0,0)` 与 `Toggle_Gyro_Control(1,0,0)` 保持 0。
- **本轮同步 ②（调用点）**：旧板 `main.c` **每圈都调 `renwu()`**，并且 `renwu_flag == 0` 时每圈 `Load(0,0)` 停车。新板原来没人调 `renwu()`（整个文件是死代码），现在在 `firmware/Core/Src/main_app.c` 主循环里加闸门：`renwu_flag != 0` 时先 `Motion_Stop()/GyroControl_Stop()/SpeedControl_Stop()` 再每圈 `renwu()`；`renwu_flag` 回 0 时调新增的 `renwu_stop()`（关角度环 + `Load(0,0)`）。
  - `renwu_stop()` 不能写成 `Toggle_Gyro_Control(0,0,0)`：那条分支会把 `saved_base_speed_*` 写回电机。
  - 任务流程用阻塞 `HAL_Delay` 分段 ⇒ 跑任务期间屏幕与遥测会停住，但 TIM6 的 5ms 环照常进中断（角度环/后台循迹环仍在跑）。

### 2.10 陀螺仪驱动 `jy61p.c`
去注释/空白后 **完全相同**（解析层没变）。旧板 USART3 + DMA 收 11 字节帧，新板一样（`firmware/Core/Src/main_app.c` 里把字节喂 `jy61p_ReceiveData()`，解析出的 `Yaw/Pitch/Roll` 写进 `g_live.*_x10`）。

### 2.11 显示 / 界面
旧板是自绘 OLED（`OLED.c` + `OLED_Data.c`，主循环里按 `menu` 0/1 切两屏、`key()` 分派）；新板换成 `kk_ui` 框架（页面栈、菜单、对话框、字模），`firmware/App/Src/app_ui.c` 负责路由与自绘页（循迹/任务/陀螺仪/电流/电机测试/设置）。这是**架构替换**，不是逐行移植；旧板的界面显示代码不需要（也不应该）搬过来。

### 2.12 主循环与时基
| | 旧板 `Haixin/Core/Src/main.c` | 新板 |
|---|---|---|
| 结构 | 裸机 superloop | `main_app.c` superloop + `kk_ui` |
| 按键 | 每圈 `key()`，menu 0/1；menu==1 时 key2/3 切 `renwu_flag` | `kk_ui` 事件（含页面栈） |
| 任务 | **每圈调 `renwu()`**；`renwu_flag==0` 时每圈 `Load(0,0)` | 主循环闸门（见 2.9） |
| 角度环 | TIM4 中断 100Hz → `GyroControl_Task()` | TIM6 5ms → `Motion_Task()` → `GyroControl_Task()` |
| 后台循迹 | TIM2 中断 10Hz → `motor_tracing_pid_0_task()` | TIM6 5ms 分频 20 → `PID_Tracing_BackgroundTask()` |
| 陀螺仪 | USART3 DMA 完成回调 → `jy61p_ReceiveData()` | 一样 |
| 舵机缓动 | 无（旧板立即写脉宽） | TIM7 → `Servo_Task()` |

旧板 `tim.c` 时间基：TIM1 `PSC=71/ARR=19999` = 1MHz/20ms = 50Hz；**TIM2 `PSC=7199/ARR=999` = 10kHz/1000 = 10Hz**；**TIM4 `PSC=7199/ARR=99` = 10kHz/100 = 100Hz**；TIM8 `PSC=71/ARR=999` = 1kHz。
新板 `bsp_board.c`：TIM1 `PSC=169/ARR=19999`（1µs/20ms = 50Hz）；TIM8 `PSC=0/ARR=7199` @170MHz = 23.6kHz；TIM6/TIM7 `PSC=169` + `Period = ms*1000-1`；编码器 TIM3/TIM4 `PSC=0/ARR=0xFFFF`。全部按 170MHz 重算过，无 F1 残留。

**本轮修的三处「在旧板能跑、在新板跑不了」的缺口**（都源于 htim2/htim4 这两个别名）：
1. `PID_Tracing_Timer_Start/Stop` 误操作 TIM6（5ms 运动节拍）→ 改软件开关 + /20 分频。
2. `Gyro_Timer_Start/Stop` 误操作 TIM7（舵机缓动 tick）→ 改空实现。
3. `Motion_Task()` 的 `MOTION_IDLE` 分支原来什么都不做，而任务流程走的就是 IDLE → 现在在 IDLE 里补跑「角度环（若使能）+ 后台循迹环」。

## 3. 刻度与量纲

### 3.1 旧板的真实刻度是 1000，不是 7200
`Haixin/Hardware/motor.c` 里写着 `#define PWM_MAX 7200`，**具有误导性**：旧板 TIM8 的 `PSC=71/ARR=999`（`Haixin/Core/Src/tim.c`）⇒ 1000 个计数就是 100% 占空比；旧 `Load()` 也没有调 `Limit()`，直接 `__HAL_TIM_SetCompare(..., abs(moto))`，写超过 999 的值会被硬件饱和到 100%。
所以旧码里的 `900` = 90% 占空比、`200` = 20%（低于 35~40% 死区，等于不动）。
新板 `MOTOR_PWM_MAX 7200`（TIM8 `PSC=0/ARR=7199`），换算系数 ×7.2。

### 3.2 已换算的数值
| 位置 | 旧值（1000 刻度） | 新值 | 说明 |
|---|---|---|---|
| `renwu.c` 45 处 `Load`/`Toggle_Gyro_Control` | 900 / 935 / 920 / 880 /… | `RW(v) = v × HP_TASK_SPEED / 900`，默认 6480 | 新增参数 `0x0304 task_speed`，默认 6480 = 7200×90% |
| `PID_tracing.c` 旧接口基准速度 | 1000 | `HP_BASE_SPEED` 默认 **6480**（=90% 占空比，>死区） | 新增 `0x0301 base_speed` 可调；2026-09-30 从 3000 抬到 6480 |
| `PID_tracing.c` 慢速接口 | 200 | `HP_BASE_SPEED_SLOW` 默认 **2500**（=34.7%，约死区下沿） | 新默认 2500 而不是 200×7.2=1440（1440 仍然低于死区） |

### 3.3 增益类参数：已按 7.2× 重标（2026-09-30 定案）
增益类参数的**量纲是「PWM 刻度 / 误差单位」**，而这两个环的输出是**直接加在左右轮上的 PWM 偏置**
（`PID_tracing.c` 的 `l = base - pid_output; r = base + pid_output`），旧板是按 1000 刻度标定的，
搬到 7200 后照抄旧值等效增益小 7.2 倍 ⇒ **全部乘 7.2**：

| 参数 | 旧码硬编码 / 原现值 | 现默认值 |
|---|---|---|
| `line_kp` | 375 | 2700（×7.2） |
| `line_ki` | 1.5 | 10.8（×7.2） |
| `line_kd` | 50 | 360（×7.2） |
| `line_ilimit` | 50 | **50（不折算）** |
| `gyro_kp` | 100 | **150（2026-10-01 原地实测重定；×7.2 的 720 会自激）** |
| `gyro_ki` | 1.5 | 10.8 |
| `gyro_kd` | 10 | **15（≈Kp/10）** |
| `gyro_ilimit` | 1000 | **1000（不折算）** |

> 角度环不适用 ×7.2：它的输出是**轮速目标**而不是「加在左右轮上的 PWM 偏置」，
> 环路增益 Kp·k_v 直接决定稳定性（k_v≈0.06 (°/s)/PWM、滞后 τ≈30~50ms ⇒ Kp 上限约 250）。
> 详见 `固件接口规格.md` 同一节与 `memory/DECISIONS.md`。

积分限幅**不乘**：它的量纲是误差本身（灰度重心 / 度），不随 PWM 刻度变。基准速度必须同时抬到
6480，否则 `base - pid_output` 会掉到静摩擦死区（~2500~2900）以下把内轮堵死。

注意 `line_ilimit 50`/`gyro_ilimit 1000` 早期文档里写过 `50→360`/`1000→7200`，那是错的（把限幅
也乘了 7.2），已作废。

默认值三处（`host_link.c` SPECS、`app_ui.c` `g_cfg` + `pull_pid_params()` 兜底、
`pid.c`/`gyro_control.c` 的 `*_FALLBACK`）与上位机镜像 `tools/host/protocol.py` 已同步；
一致性核对 `python tools/host/check_param_table.py` 已自动化（解析固件源码，不再手抄表）。
