# 全地形机器人 · 上位机

无线串口上位机：实时遥测、在线调参、录制回放。Python + tkinter + pyserial，**不依赖网络、不依赖 matplotlib**。

---

## 快速开始

**方式一（推荐）**：双击 `run_host.bat` —— 直接进**模拟器模式**，没有车、没有串口也
能完整看到界面在动。

**方式二（命令行）**：

~~~bat
cd tools\host
python main.py                 :: 模拟器模式
python main.py --port COM5     :: 连真实串口（无线下载器的虚拟串口）
python main.py --csv out\host\host_20260924_101530.csv   :: 回放一段录制
python main.py --offline       :: 只开界面，不自动连接
~~~

**方式三（零依赖备胎）**：`python main.py --ui tk` —— 用 tkinter 版界面（样式朴素，
但只需要 stdlib + pyserial）。

依赖：
- **界面**：`pip install PySide6 pyqtgraph`（默认界面库，深色仪表盘风格）。没装也能启动，
  会自动退回 tkinter 版并提示。
- **串口**：`pyserial`（已装 3.5）。缺它只影响真实串口，模拟器与回放照常可用。

> 两个界面**共用同一套逻辑**（`protocol/transport/device/field/simulator`），
> 所以 100 个测试对两边都有效。改界面不用担心把协议改坏。

| 命令页 | 启动任务 A/B/C、停止、陀螺校准、清故障、软复位、遥测频率、车上记录开关 |

## 三种模式

| 模式 | 说明 |
|---|---|
| **串口** | 连无线下载器的虚拟串口（主控侧是 LPUART1：PC1=TX / PC0=RX），默认 115200 8N1 |
| **演示数据** | 内置小车模型，**收下发帧并正确应答**，所以在离线状态下改参数、发命令、录制回放全部可验证 |
| **回放** | 把录制的 CSV 按时间轴重新吐出来，用于反复复现一次失败的过程 |

倍速可选 1/2/5/10/20 倍，方便快速跑完一段脚本。

### 演示数据源（没有真车时用）

没有车、没有串口时，界面靠一个**信号发生器**喂数据：循迹偏差按正弦摆动、
灰度掩码由偏差反推、轮速/电流/电压互相关联、还会注入一次"堵转"演示告警。

**它不是赛道仿真**（没有场地、障碍、计分、循迹路线）—— 上一版那套赛道
仿真已经被删掉了，因为跑出来不对、也没有参考价值。它**只有一个用途**：
手边没车时能看波形、能试调参（`line_kp` 调大，偏差摆幅会变小，和真实闭环一个趋势）。

## 调参工作流（这套界面就是围着它做的）

1. **连上** —— 串口或演示数据；波形页勾上要看的两三个通道（**每通道独立量程**，不会互相压扁）。
2. **跑一段，点「存为基线」** —— 当前窗口的波形被冻结成虚线。
3. **改参数** —— 参数页双击改，或到参数总览页看谁贴着边界。
4. **再跑一段** —— 实线是新的、虚线是旧的，两条一叠，改好改坏一目了然。
5. **看底部指标** —— 每个可见通道的 **峰峰 / 均值 / 标准差 / 过零次数**，
   不用靠眼睛数"晃了几下"。
6. 满意了「保存预设」，把 preset 和 config 一起带走。

配套的几件小事：

* **鼠标移到波形上**：点线游标 + 各通道该时刻读数（`t -3.42s 航向=+12.3° 左轮速=68.0 mm/s …`）。
* **参数总览页**：每个参数一条，画出当前值在允许范围里的位置（绿=有余量 / 黄=接近边界 /
  红=越界）；**带 `*` 的是与默认值不同的项**，一眼看出这次调了什么。
* **会话记忆**：模式 / 波特率 / 倍速 / 窗口 / 勾选的通道存在 `tools/host/config.json`，
  下次打开自动恢复。

## 自测

~~~bat
selftest.bat            :: 等价于 python tests\run_all.py
~~~

或分别跑（注意界面测试要单独一个进程，见 run_all.py 里的说明）：

~~~bat
python tests\test_protocol.py    :: 协议编解码 40 项（CRC 用标准校验值 0x29B1 锚定）
python tests\test_link.py        :: 链路端到端 25 项（无需硬件）
python tests\test_ui_smoke.py    :: 界面冒烟 8 项（窗口摆到屏幕外，不需要人看）
~~~

其中链路测试覆盖：握手、读全部参数、改参数、超范围拦截、命令、黑标事件、
坡道/卡死标志、CSV 录制回放、CRC 计数为 0、以及"Kp 变大追得更紧"的行为断言。

## 界面实现

| `ui_qt/` | **默认界面（PySide6）**：`theme.py` 深色 QSS、`widgets.py` 自绘控件（灰度条/表盘/速度条/参数总览）、`window.py` 主窗口（工具条 + 左侧实时图形 + 波形\|参数\|参数总览\|命令\|记录\|日志） |

~~~bat
set QT_QPA_PLATFORM=offscreen
python tests\test_ui_qt.py        :: 会真的 grab 一张 out/host/ui_qt_smoke.png
~~~

## 与固件的对接

协议全文（含 C 参考实现与改动清单）见 [上位机通信协议.md](../../docs/上位机通信协议.md)。

**固件侧目前还没实现**，需要补的（已核实）：

1. `Core/Src/board.c` 里 `hdl` 句柄存在但 **LPUART1 从未初始化** —— 先补 init + 接收中断环形缓冲。
2. 新建 `App/Svc/host_link.c`：组帧、CRC、收帧状态机、参数表、命令分发。
3. 把 PID 参数从 `#define` 改成可写变量并入参数表。
4. 主循环按设定频率发遥测帧。

建议验证顺序：只发 TEXT → 证明链路通 → 发 TELEM 看波形 → 读参数 → 改参数用 RTT 对照 → 最后接状态机。

## 合规提醒（重要）

比赛规则明确：**参赛作品应自主控制，不允许任何形式的远程控制干预**。
所以本上位机的命令页**只能在运行间隙使用**（调参、导出黑匣子），
**绝不能用于比赛运行中的干预**。规则与场地见 [全地形机器人比赛规则与场地.md](../../docs/全地形机器人比赛规则与场地.md)。

## 已知限制

- **车上的参数表还存在固件里**：本上位机改了参数只是改 RAM，重启就没了；要掉电保存需点"写Flash"（固件侧实现后）。
- 参数表指纹用于发现固件与上位机不一致，但**指纹一致不代表语义一致**，改参数含义时要两边一起改。
- `wheel_dia` / `wheel_base` 默认值是 65mm / 150mm，**待实测**，里程换算依赖它们。
- 模拟器是简化模型（单轨 + 一阶转向延迟），用于验证链路与调参手感，**不能替代实车标定**。
- CSV 回放时上行命令不会真的执行（回放是只读的）。
