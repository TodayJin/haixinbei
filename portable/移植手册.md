# 全地形机器人固件移植手册

> **这份手册解决一件事：把这套固件搬到一块新的主控/新板子上，并证明每一步真的对了。**
> 移植包在 `portable/firmware/`（可移植模块 + 参考板级适配层），独立上位机在 `portable/host/`。
> 逐函数接口契约见附录 [`docs/移植与接口说明.md`](docs/移植与接口说明.md)，
> 包内文件清单见 [`firmware/README.md`](firmware/README.md)。

**一句话结论**：这套固件是**分层**的 —— 通信链路、任务编排、参数与 NVRAM、自愈、显示中间件
**一行都不用改**；要重写的只有三类东西：**板级适配层（`board.c/.h`）**、**BSP 的定时器/引脚
（`bsp_board.c`）**、以及**机械参数（在参数表里，不用改代码）**。剩下的全是"按顺序做 + 每步验证"。

## 0. 怎么用这份手册

1. **先读第 1、2 节**，把"哪些能照搬、哪些必须重写、硬件够不够"定下来。第 2 节有几个
   问题必须**换板子之前**回答完，事后补代价很大（尤其 Flash 尾部页面和擦除粒度）。
2. **按阶段动工**：①→⑨ 顺序不能跳。每一阶段都有**验证判据**，判据不过不要进入下一阶段 ——
   这套固件的失败模式大量是"静默"的（DMA 不传、字模缺字、中断没进），只看"编过了"会翻车。
3. **每个阶段都先只接调试口**（RTT + SWD），最后才上电机/舵机。
4. 遇到现象与预期不符，先去第 13 节"常见移植坑"对号；再不行回附录查接口契约。

> 全项目唯一权威的"当前状态"是 `project/` 下的源码与本手册引用行号；
> 本文所有结论都按 `portable/firmware/**` 与 `project/firmware/**` 的实际代码核对过。

## 1. 目标与边界：什么带走、什么重写

### 1.1 必须带走（一行不用改）

| 能力 | 文件 | 为什么跟板子无关 |
|---|---|---|
| 上位机通信协议 + 58 项参数表 | `App/Svc/host_link.c/.h` | 只依赖 `board_dl_*()` 这一组板级函数 |
| 协议↔业务胶水 / 远程驾驶 / 看门狗 | `App/Svc/host_ext.c/.h` | 只调 `Motion_*`/`SpeedControl_*`/`Servo_*` |
| 任务编排（解析 / 解释器 / 落盘） | `App/Svc/task_prog.c`、`task_run.c`、`task_store.c` | 纯逻辑 + Flash 页号常量 |
| 设置与标定存档 | `App/Svc/nvram.c/.h` | 只依赖"最后一页在哪" |
| 自愈：I2C 总线看门狗 / 显示故障自愈 | `App/Svc/bus_health.c`、`disp_heal.c` | 纯决策逻辑，动作交给板级 |
| 三层控制环（速度/角度/循迹） | `App/Svc/speed_control.c`、`gyro_control.c`、`PID_tracing.c`、`tracing.c`、`pid.c` | 输入是编码器计数/灰度/姿态，输出是 PWM 刻度 |
| 运动调度与节拍统计 | `App/Svc/motion.c` | 只认 TIM6 5ms 回调 |
| 显示中间件 | `Middlewares/kk_ui/`、`Middlewares/kk_oled/` | 只认 `board_i2c()` 与画图 API |
| UI 示例（15 页 / 8 个自定义页） | `App/Src/app_ui.c`、`App/Inc/app_ui.h` | 可整份当模板改 |
| 字模与字模工具 | `App/Fonts/`、`tools/font/` | u8g2 格式，与 MCU 无关 |
| RTT 日志 | `Middlewares/SEGGER_RTT/` | 与调试器绑定，与板子无关 |

**"不用改"的前提**：你保留了这些对外符号的语义（`Load()` 正 = 前进、`keys_raw()` 位定义、
`Yaw/Pitch/Roll/Gyro_Z` 全局量、`board_dl_send()` 等）。换外设时改**驱动**，别改上层调用点。

### 1.2 每块板必须重写（三类）

| # | 东西 | 文件 | 具体是哪些 |
|---|---|---|---|
| 1 | **板级适配层** | `参考板级适配层/board.c/.h` | 时钟/PLL、I2C 速率与时序、三条串口（含 LPUART1 的 DMA）、INA226、按键 GPIO、蜂鸣器与保险丝、I2C 总线恢复 |
| 2 | **BSP** | `App/Bsp/bsp_board.c/.h` | TIM1 舵机、TIM8 电机 PWM、TIM3/TIM4 编码器、TIM6/TIM7 5ms、8 路数字灰度；`motor.c` 的引脚映射、`buzzer.c` 的有效电平 |
| 3 | **机械参数** | **不改代码**，改参数表 | `0x0305 counts_per_rev`、`0x0306 wheel_dia`、`0x0307 wheel_base`、`0x0308 speed_full_counts`、`0x0605/0x0606` 速度环前馈 |

⚠️ 有一类东西**看起来该重写，其实不能乱动**：
- `App/Svc/**` 里的常数（`GYRO_DT=0.005f`、`SPEED_PERIOD_MS=5.0f`、阈值、安全上限）——
  改它们等于改控制律，需要重新整定，不是"移植"。
- `motor.c` 里右路取负、`encoder.c` 里右路取负 —— 这是**左右电机镜像安装**的物理事实，
  与新板无关；除非你的机械结构不再镜像，否则别动。

### 1.3 判断原则

一条规则就够：**能只通过 `board.h` 的宏和 `bsp_board.c` 的定时器配置表达出来的差异 → 移植；
需要改 `App/Svc/` 里的算法/常数 → 那是换了一套车，要重新标定。**

## 2. 移植前检查表

### 2.1 资源清单（先填这张表，缺一项就先解决再动工）

| 项 | 本工程实际值 | 你的板子 | 怎么核对 |
|---|---|---|---|
| 主控 Flash | **128KB**，但固件只许用 **116KB**（页 58 起是任务区+NVRAM） | ☐ | `arm-none-eabi-size build-app/*.elf`，`.ld` 的 `FLASH LENGTH` |
| RAM | 96KB SRAM + 32KB CCM（当前 data+bss ≈ 37KB） | ☐ | `.map` 里 `.data+.bss`，再留 8KB 栈 |
| 是否需要 FreeRTOS | **不需要**。本工程是裸机 + 一组中断（SysTick、I2C1_EV/ER、DMA1_Ch1/2/3、USART3、LPUART1、TIM6_DAC/TIM7_DAC） | ☐ | 主循环是 `while(1)`，见 `main_app.c:207` |
| I2C | 1 条（OLED 0x3C + INA226 0x40 + 灰度模块 0x01 共用） | ☐ | 至少要 1 条 I2C，速率 100k/400k 可调 |
| 串口 | 3 条：USART3(JY61P 115200)、LPUART1(上位机 921600)、UART4(灰度备用 115200) | ☐ | 少一条可以用软件模拟吗？UART4 可省（灰度回落到数字口） |
| 定时器 | TIM1(舵机 50Hz)、TIM8(电机 PWM 23.6kHz)、TIM3+TIM4(编码器)、TIM6+TIM7(5ms) = **6 个** | ☐ | 可用通用定时器替代，但**必须有一个 5ms 硬节拍** |
| DMA | I2C1_TX 1 路、LPUART1 RX/TX 各 1 路（共 3 路） | ☐ | DMA 不是硬需求：屏可阻塞刷、串口可降速，但实时性会差 |
| Flash 擦除粒度 / 最后一页 | **4KB 块擦除（不是 2KB 页）**；最后一页 `0x0801F800`（页 63，块 31） | ☐ | **必须查手册确认**：页数×页大小、擦除粒度、是否单 bank |
| 显示控制器 | SSD1315（128×64，I2C，地址 0x3C，内部电荷泵 `8D 14`） | ☐ | 换控制器只改 `kk_oled_driver.c` 的初始化序列 |
| 编码器 | 2 路 AB 相，进 TIM 编码器模式（4 倍频） | ☐ | 没有编码器 → 速度环失去反馈（误差恒为满量程、PI 积到限幅）⇒ 只能 `Load()` 走开环 PWM |
| 灰度 | 8 路（I2C 模拟量优先 / UART 备用 / PA0–PA7 数字口兜底） | ☐ | 少于 8 路要改 `TRACE_CAL_CH` 与权重 |
| IMU | JY61P（USART3，11 字节 0x55 帧，100Hz） | ☐ | 换 IMU 只改 `jy61p.c`，保持 `Yaw/Pitch/Roll/Gyro_Z` 全局量 |
| 电源监测 | INA226（I2C，5mΩ 分流，CAL=1024） | ☐ | 没有它 → 低压保护失效，可编掉但**别上车跑** |
| 调试口 | SWD 两线 + 一条串口（上位机链路可以从同一个口引出） | ☐ | 至少要 SWD，否则只能靠屏猜 |

### 2.2 六个必须先回答的问题

1. **Flash 尾部有没有 6 页连续空间？** 任务存储要页 58–61（8KB），NVRAM 要页 63，
   而且擦除粒度是 4KB 块 → 实际需要**块 29/30/31** 三块。页 62 会被 nvram 的块擦连带擦掉。
2. **Flash 是单 bank 还是双 bank？** 单 bank 擦写会**停止取指约 30ms**（本工程靠"运动中绝不写"
   规避）。双 bank 可以边跑边写，但代码里的擦除地址与块号逻辑要重新核对。
3. **有没有一个稳定的 5ms 定时器？** 三层串级的 `dt` 全部按 5ms 写死（`GYRO_DT`、
   `SPEED_PERIOD_MS`、`BSP_TRACE_PERIOD_MS`）。
4. **I2C 上拉和总线电容够不够 400kHz？** 本工程实测 400kHz + **中断刷新**稳，400kHz + **DMA**
   偶发黑屏（见坑 2）。新板若排线更长，先按 100kHz 起。
5. **编码器计数够不够？** 5ms 窗口内计数不能越过 ±32767。本车 1456 计数/圈、
   5ms 最多几十个计数，很安全；换高线数编码器要复核。
6. **上位机链路的波特率能到 921600 吗？** 取决于 USB 转串口那侧（见第 11 节的探针坑）。

### 2.3 需要先拍板的取舍（本工程里各有一条现成路径）

| 取舍 | 选 A | 选 B |
|---|---|---|
| 屏刷方式 | **IT**（稳，推荐，`-DKK_UI_REFRESH_MODE=KK_UI_REFRESH_IT`） | DMA（更快，但 400kHz 下偶发黑屏；`kk_ui_config.h` 的默认值就是它 ⇒ **不传 -D 就是 DMA**） |
| 是否用角度环 | 用（需要 JY61P，任务里的转弯/摆正靠它） | 不用（`MOTION_TRACE` 单环循迹也能跑，只是没有航向锁） |
| 灰度通道 | I2C 模拟量（稳定、可标定） | 数字口 0/1（够用、但丢阈值信息） |
| 任务存储 | 开（页 58–61） | 不开（把 `task_store.c` 编掉，省 8KB Flash） |

## 3. 阶段① 建工程与时钟

### 做什么

1. 用 CubeMX/CubeIDE 建空工程，选新主控，**只配 HAL + CMSIS + 启动文件 + 链接脚本**，
   外设全部手写（本工程不用 CubeMX 生成的外设初始化）。
2. 把 `portable/firmware/App/`、`Middlewares/`、`参考板级适配层/*` 拷进工程。
3. 写自己的 `main.c`：`HAL_Init()` → `board_clock_init()` → 打印 RTT。
4. 改链接脚本：`FLASH LENGTH` 必须给任务区/NVRAM 留位置（本工程 128KB 只给 116KB，
   见 `参考板级适配层/STM32G474RBTx_FLASH.ld:25`）。

### 关键位置

| 文件 | 看什么 |
|---|---|
| `参考板级适配层/board.c:16-100` | `board_clock_init()`：开 PWR、关 UCPD 死电池、HSE 25MHz + PLL /5×68/2=170MHz、`FLASH_LATENCY_4` |
| `参考板级适配层/STM32G474RBTx_FLASH.ld:23-25` | `CCMRAM 32K / RAM 96K / FLASH 116K` |
| `project/firmware/Makefile` | 编译选项、`-Os -g3`、`--specs=nano.specs`、`-MMD -MP` 头文件依赖 |

### 验证判据

- **必须出现**：RTT 打印 `CLK: HSE=1 PLL=1 SYSCLK=170000000 Hz` 这一类行
  （`main_app.c:73`），并且 `clock_report_t` 里的 `pclk1_hz/pclk2_hz` 与你算的一致。
- **必须核对**：`FLASH_LATENCY`。主频 170MHz 要 4 个等待周期；写小了会随机取指错，
  现象是"跑一会儿莫名其妙 HardFault"。
- **不要**在这一步接任何功率器件。板子上只有调试口供电时，5V/12V 轨可能微亮（体二极管倒灌），
  属正常。

### 常见错

- 只改 `HSE_VALUE` 宏没改 PLL 系数 → 时钟对了但串口波特率全错。
- CubeMX 生成的 `SystemClock_Config()` 与本工程 `board_clock_init()` 重复定义 → 链接冲突。
- 忘了 `__HAL_RCC_PWR_CLK_ENABLE()` 就调 `HAL_PWREx_DisableUCPDDeadBattery()` → 静默无效（坑 3）。

## 4. 阶段② 板级适配层 `board.c/.h`

这是**唯一必须逐函数写对**的一层。完整原型表见附录第 1 节，这里给"做什么 + 判据"。

### 4.1 时钟与时间基

`board_clock_init()` 之外，"时间"这一项**不在 `board.h` 里**：它由 `HAL_Init()` 的 SysTick
提供 `HAL_GetTick()`，全工程所有超时/防抖都基于它。移植时只需确认：

- `HAL_GetTick()` 1ms 递增（SysTick 重载值随主频自动算，CubeMX 的 `HAL_InitTick()` 已处理）；
- 中断优先级分组是 `NVIC_PRIORITYGROUP_4`（全抢占位）。

### 4.2 I2C1（屏 + INA226 + 灰度共用一条总线）

要实现：`board_i2c_init_hz()`（可反复调、记住速率）、`board_i2c_enable_dma()`、
`i2c_read_reg/i2c_write_reg/i2c_probe`、`board_i2c_report()`、`board_i2c_watchdog()`、
`board_i2c_bus_recover()`。

- 时序用 `i2c_timing(pclk, scl_hz)` 现算（`board.c:235-255`：`t_low=520ns/f`、`t_high=480ns/f`），
  不要抄别人的魔数 —— `TIMINGR` 依赖 PCLK，换主频必错。
- **总线恢复**（`board.c:379-412`）：把 SCL 配成开漏 GPIO，打 9 个时钟 + STOP，再重配 I2C。
  用途：从机在事务中间掉电/复位后，HAL 只会一直超时，**永不自愈**。
- **看门狗**：每次读写后 `board_i2c_report(ok)` → 连续失败 5 次置"待恢复"，由
  `board_i2c_watchdog(bus_idle)` 在**总线空闲**时执行恢复（`bus_health.h:24-25`）。
- `board_i2c_enable_dma()` 里 **`__HAL_RCC_DMAMUX1_CLK_ENABLE()` 必须显式调用**
  （`board.c:332`）—— 漏了 DMA 请求不路由，异步传输永不发生且不报错。

### 4.3 三条串口

| 串口 | 要求 | 验证 |
|---|---|---|
| USART3（JY61P） | 115200，**中断收 + 256B 环形缓冲**，`board_jy61_get_byte()` 非阻塞取 | 插模块后 `jy61p_frame_count()` 每秒涨 ≈100 |
| LPUART1（上位机） | 921600，收 = DMA 循环搬运（2048B），发 = DMA 槽位队列（8 帧），队列满丢帧计数 | RTT `HOST:` 行 `tx` 每秒 +≈200、`txdrop=0` |
| UART4（灰度备用） | 115200，阻塞读（超时 2ms/字节） | 灰度模块回 `{0x75,...,0x11/0x15}` 帧 |

`board_dl_baud()` 是波特率的**唯一真值**（现 921600，`board.c:665` 的 `#define DL_BAUD`），
上位机默认值必须与它一致；不要在别处再抄一份数字。

### 4.4 GPIO：按键与蜂鸣器

- 五向键：5 路输入 + **内部上拉**，低有效 → `keys_raw()` 返回 `bit0=上 … bit4=中`（1=按下）。
- 蜂鸣器：高有效（低边 S8050），除 `board_buzzer_init/off` 外必须有
  `board_buzzer_mark_on()` + `board_buzzer_safety()` 这对"保险丝"：开响记时刻，
  **5ms 中断**里检查，响超 150ms 强制掐掉。这是"主循环卡死也不会一直响"的唯一保证
  （`main_app.c:328`，坑 9）。

### 4.5 电源监测 INA226

`ina226_init()` 写 `0x4127`（1 次平均/1.1ms+1.1ms/连续）、`CAL=1024`（5mΩ → 1mA/bit），
读电压 1.25mV/bit、电流 1mA/bit、功率 25mW/bit（`board.c:452-510`）。
移植时只需改：I2C 地址、分流电阻对应的 `CAL`、以及参数表 `0x0501/0x0502/0x0503`
（标称母线电压/堵转电流/低压阈值）。

### 4.6 Flash（**不在 `board.h` 契约里**）

`board.c` **没有任何 Flash 代码**：擦写由 `nvram.c` 与 `task_store.c` 直接调 `HAL_FLASH`。
所以换芯片时，Flash 的"页面/块/地址"三类常量要在这两个文件里改（见第 8、9 节）。
这是移植时最容易漏的一项 —— 因为 `board.h` 里找不到它。

### 验证判据（本阶段全过才能继续）

- RTT 出现 `I2C1 @400kHz`，随后 I2C 扫描能扫到 **0x3C（屏）+ 0x40（INA226）**。
  （扫描代码不在移植包里，自己写 10 行 `i2c_probe()` 循环即可。）
- `keys_raw()`：按每个方向，RTT 打印的位**只有一位变化**；五键同时为 1 说明初值/上拉配错（坑 10）。
- `host_link_init()` 后 RTT 出现 `host link init OK`，且 `board_dl_baud()` 返回值与上位机一致。
- `board_i2c_bus_recover()` 能手动调用：调用前后 `board_i2c_recover_count()` +1。

## 5. 阶段③ BSP：电机 / 舵机 / 编码器 / 按键 / 蜂鸣

### 5.1 电机 PWM：刻度 0..7200 与 ARR 的关系（**最常被搞错**）

```c
/* bsp_board.h */
#define MOTOR_PWM_MAX   7200
#define MOTOR_PWM_MIN  (-7200)

/* bsp_board.c tim8_motor_init() */
htim8.Init.Prescaler = 0U;
htim8.Init.Period    = MOTOR_PWM_MAX - 1U;   /* = 7199 */
```

关系是：**`CCR` 直接等于"刻度"，满量程 = `ARR+1 = 7200`**，所以 PWM 频率 =
`TIM_CLK / 7200`。本板 TIM8 时钟 170MHz → **23.6kHz**（避开人耳与电机啸叫）。
换主频/换定时器时，只要保住"**ARR+1 = 7200**"这一条，上层所有 PID 参数与参数表刻度
就完全不用重标定；如果新定时器做不到这么大的 ARR，就必须改 `MOTOR_PWM_MAX`，
同时把参数表里所有 PWM 刻度（`0x0301/0x0303/0x0605/0x0606/0x0104`…）一起等比换算。

驱动方式（`motor.c`）：每电机**两根输入都接 PWM**（AT8236 这类双输入 H 桥），
正速度 = IN1 出 PWM/IN2 恒低，负速度反之；**右路符号在 `motor.c` 内部取负**（镜像安装）。

### 5.2 舵机：50Hz / 1µs 刻度

```c
htim1.Init.Prescaler = 170U - 1U;   /* 1MHz → 1 tick = 1µs */
htim1.Init.Period    = 20000U - 1U; /* 20ms → 50Hz */
/* 于是 CCR 直接就是脉宽 µs，Servo_SetPulse() 夹 500..2500 */
```

⚠️ `bsp_servo_init()` **只启动 CH1/CH2**：CH3/CH4 一旦 `HAL_TIM_PWM_Start()`，就会一直输出
初始化时的 `oc.Pulse=500`（0° 位），而 `Servo_SetPulse()` 只认 1/2 号 → 插在 3/4 号座上的
舵机被"钉死"且松不掉（`bsp_board.c:231-245`）。要用 3/4 号：先补 `servo.c` 的 case，再补启动。

### 5.3 编码器：TIM 编码器模式

```c
enc.EncoderMode  = TIM_ENCODERMODE_TI12;   /* A/B 两相双边沿 → 4 倍频 */
enc.IC1Filter    = 10U;                    /* 霍尔 + 100nF，数字滤波取大一点 */
h->Init.Prescaler = 0U; h->Init.Period = 0xFFFFU;
```

- 读法：`Encoder_ReadDelta()` 读 16 位 CNT（强转 `int16_t` 拿符号）后**立即清零**；
  **只许速度环每 5ms 调一次**，别人调会偷走计数。
- 计数换算：`counts_per_rev = 线数 × 4 × 减速比`（本车 13×4×28 = **1456**，参数 `0x0305`）。
- **符号约定**：两轮都朝前进方向滚时两路计数**都为正**。本车电机镜像安装，所以
  `encoder.c` 只翻右路、`motor.c` 只翻右路 —— 两边**必须配套**（坑 11）。

### 5.4 按键 / 蜂鸣器 / 周期任务

- 按键：`board.h` 的 `keys_raw()` 给 UI；`App/Bsp/key.c` 是旧板遗留单键扫描，可留可删。
- 蜂鸣器：见 4.4。
- 周期任务（`bsp_periodic_start()`）：TIM6 → `Motion_Task()`（5ms），TIM7 → `Servo_Task()`（5ms），
  NVIC 优先级 **6**（`bsp_board.c:266-269`；实测提到 0 会让原地转失控，坑 12）。
  两个中断都走 `HAL_TIM_PeriodElapsedCallback()`（`main_app.c:323-335`）：
  **这个回调必须自己实现**，否则 `HAL` 的弱回调什么都不做，控制环永远不会跑。

### 验证判据

- 上电 RTT 出现 `encoder + speed loop init OK`，之后每秒有 `MOTION:` 行；
  `enc l/r` 在**手转轮子**时变化，且前进方向推两轮都为正。
- `ISR: avg=… max=… over=0` —— `over` 必须 **0**；涨了就说明有长操作堵了 5ms 中断
  （擦 Flash、关中断太久、`HAL_Delay` 进了中断）。
- 万用表/示波器：PC6/PC7 占空比随 `Load()` 变化；不发 `Load()` 时 PWM 恒 0（上电安全）。
- 舵机：只插 1/2 号座，`Servo_SetAngleDev(1, 90, 0)` 后信号脚 1.5ms 脉宽。

## 6. 阶段④ 控制链路：节拍与三个环

### 6.1 主循环节拍

```
主循环（main_app.c:207-315，实测 ~235Hz）：
  trace_cal_poll → read_tracing_data → 喂 JY61 字节
  → app_ui_tick（UI 绘制，自带 20ms 节流）
  → nvram_service（Flash 擦写排在绘制之后）
  → host_link_poll / host_link_tick_1hz
  → 每 20ms KK_UI_Invalidate
  → nvram_poll（200ms 检查一次设置是否变了）
  → TaskRun_Tick（任务解释器，5ms 逻辑但跑在主循环）
  → HAL_Delay(2)
```

⚠️ `HAL_Delay(2)` 是**空转等 SysTick**，不是真睡眠；它在主循环末尾，不影响 5ms 中断。

### 6.2 三个环的单位与 dt 假设

| 环 | 文件 | 输入 | 输出 | dt 假设 |
|---|---|---|---|---|
| 循迹环 | `PID_tracing.c` | 8 路灰度重心 1..8（正中 4.5） | 差速 或 **目标转率 °/s** | 10Hz 后台任务 |
| 角度环 | `gyro_control.c` | 目标航向（°）/ `Yaw`/`Gyro_Z` | 左右轮目标速度（PWM 刻度） | **5ms**（`GYRO_DT=0.005f`） |
| 速度环 | `speed_control.c` | 目标 PWM 刻度 / 编码器计数 | PWM（±7200） | **5ms**（`SPEED_PERIOD_MS=5.0f`） |

- 速度环测速是 **最近 4 拍（20ms）滑动平均**，但控制节拍仍是 5ms ——
  不要为了"测速更准"去改 TIM6 周期，那会把角度环的 dt 一起弄错。
- 角度环失联保护：500ms 没有新姿态帧 → `Motion_GetFault()=MOTION_FAULT_GYRO_STALE` 并停车。
- 所有阈值/增益都在参数表里（`0x01xx` 角度环、`0x02xx` 循迹、`0x03xx` 速度/机械、
  `0x04xx` 转弯、`0x05xx` 电源、`0x06xx` 速度环 PI），改这些**不需要重编**。

### 验证判据

- `MOTION: mode=…` 与预期一致（0 空闲/1 角度/2 循迹/3 串级）。
- 手转轮子看 `v mm/s l/r`：两轮同向推 → 两个正数；一正一负 = 符号约定反了。
- 给一个恒定 PWM（模块测试页或 `Load()`）：`tgt` 稳定、`out` 与 `tgt` 接近，`fault=0`。
- 原地转：给 `GyroControl_SetTargetAngle(90)`，`yaw` 单调逼近且末值稳定在 ±2° 内。

## 7. 阶段⑤ 通信链路：LPUART1、DMA、看门狗

### 7.1 链路结构（`board.c:559-913`）

```
PC ── USB 转串口（无线下载器）── LPUART1 921600 8N1 ── 车
   收：DMA1_Ch2 循环搬运 2048B → 主循环按 CNDTR 取指针 → 逐字节喂 host_link 状态机
   发：DMA1_Ch3 槽位队列（8 帧）→ 队列满丢帧并计数（宁可丢遥测，不让控制环等串口）
```

引脚：`PC0=RX`、`PC1=TX`、AF8（查手册确认过，别靠记忆猜 AF 号）。

### 7.2 协议要点

帧 = `A5 5A | type | seq | len | payload | CRC16`，CRC16/CCITT-FALSE（`"123456789"`→`0x29B1`）。
CRC 错**只前移 1 字节重同步**，所以上电乱码/插拔/干扰能自愈。
`HELLO` 帧带：固件版本、协议版本 v2、**参数表 CRC**、遥测频率、名字 `quandi-car`、能力位。

### 7.3 超时与看门狗

| 机制 | 值 | 作用 |
|---|---|---|
| 遥测 | 200Hz（可 1..200） | 上位机据此判断链路活性 |
| 驾驶看门狗 | **500ms** 无合法帧 → 自动停车 | 断链/关网页不会让车继续跑 |
| 发送队列 | 8 帧（≈1KB，@921600 ≈11ms） | 满了丢帧并计数 `txdrop` |
| 收缓冲绕圈 | `rxover` 计数 | 非 0 说明主循环太久没取数据 |

### 验证判据

1. **只看 RTT**：`HOST: rx=0 tx=N crc=0 resync=0 sets=0 hz=200 txdrop=0 rxover=0`，
   `tx` 每秒 **+≈200**。`txdrop/rxover` 必须 0；非 0 就先降遥测频率。
2. **接上位机**：握手成功、参数表 CRC 一致（第 11 节）。
3. **跑够 10 分钟**：`crc=0 resync=0`。这两个数涨说明线太长/波特率太高/没共地。
4. `host_link_send_text("hello")` 单测一次：上位机日志里能看到这行。

## 8. 阶段⑥ NVRAM：最后一页、v13、CRC、迁移

### 8.1 布局（`nvram.c:20-180`）

```
地址：0x0801F800 = Flash 最后一页（页 63，块 31）
记录：magic(4)="HXB1" | version(2)=13 | length(2) | CRC32(4) | payload | pad
写入：按 64 位双字写 ⇒ 整条记录必须是 8 的整数倍（编译期断言挡住）
```

### 8.2 时序（**不要改**）

| 参数 | 值 | 理由 |
|---|---|---|
| 检查周期 | 200ms | 主循环里比快照 |
| 防抖 | 改动后静 1.5s 才写 | 用户可能在菜单里连改好几项 |
| 失败退避 | 5s，翻倍封顶 60s | 页坏了不至于每 1.5s 擦一次 |
| 写前 | 清 `FLASH_FLAG_ALL_ERRORS` | 复位后 SR 里残留 `PGAERR/PGSERR` 会让第一次擦除直接失败 |
| 写时 | 运动中绝不写；`OLED_IsBusy()` 让路；开机绝不写 | 擦写停 CPU ~30ms，且与屏抢 I2C |

### 8.3 版本迁移规则（**加字段前必读**）

- **只往末尾加** ⇒ 旧记录按 `length` 取前缀，新字段补默认值（v1→v2、v5→v6 都是这么做的）。
- **占用 pad 区** ⇒ `NVRAM_VERSION += 1` **且**在 `nvram_init()` 里对 `version < 新版本`
  显式赋默认值。反例：v13 把 `task_speed` 从 `pad7` 抠出来，payload 长度没变；
  不显式迁移的话，v12 老存档在这 4 字节上是 0 → 任务基准速度 0 → `TaskRun_Start()`
  切到 pivot 增益 → **左右轮对转**。
- 加字段后必须同步 `nvram.h` 的版本注释与 `test/t_nvram.c`（项目工程内）。

### 8.4 掉电风险（如实说）

没有掉电检测：写到一半断电，记录 CRC 会失效 → 下次开机当"没有存档"（用代码默认值）。
可接受，因为记录是一次性整条重写的，不会出现"半个值"。**但**：不要在车上运动中改设置
（固件已禁止运动中擦写）；也不要指望它替代黑匣子。

### 验证判据

- RTT 打印 `nvram loaded=0`（第一次烧录）→ 改一个设置 → 屏显示"正在保存/保存成功" →
  断电重启 → `nvram loaded=1` 且设置还在。
- 用调试器直接读 `0x0801F800` 前 12 字节：magic=`48 58 42 31`、version=`0D 00`、
  length 合理、CRC 非 0/非 FFFFFFFF（PC 端可重算 CRC32 校验）。
- 全片擦除后 `0x0801F800` 应是全 `0xFF`，且**开机不会写它**（开机绝不写）。

## 9. 阶段⑦ 任务存储：页 58–61 与 4KB 块

### 9.1 页分配（`task_store.h:5-61`）

| 区域 | 页 | 地址 | 内容 |
|---|---|---|---|
| 固件镜像 | 0–57 | `0x08000000`–`0x0801CFFF` | `.ld` 的 `FLASH LENGTH = 116K` 挡住越界 |
| 任务目录 | 58 | `0x0801D000` | magic/ver/count/seq + 8×40B 记录 |
| 任务程序区 | 59–61 | `0x0801D800`–`0x0801EFFF` | 6144B，紧凑摆放，8 字节对齐 |
| 空 | 62 | `0x0801F000` | nvram 的 4KB 块会连带擦它，所以空着 |
| NVRAM | 63 | `0x0801F800` | 设置/标定 |

⚠️ **本板擦除粒度是 4KB 块，不是 2KB 页**（`task_store.c:100-111` 实测）：
块号 = 页号/2，写页 58 会连带擦掉页 59。所以整片必须按块划：块 29 = 页 58/59、
块 30 = 页 60/61、块 31 = 页 62/63。**谁都不许擦自己块以外的块** —— 这就是本模块和
NVRAM 能共存的全部理由。

### 9.2 写入语义

- 写一个任务 = 擦块 29 + 擦块 30 + 整份重写（2 次 4KB 擦 + 8KB 编程）。
- **先擦目录页**：掉电中断时车上看到的是"没有任务"，而不是"半个新程序配旧偏移"
  —— 只有前者安全（跑错轨迹比不跑更糟）。
- 每条记录独立校验（结构 + CRC16），坏记录算空槽；目录 magic 坏了整片算空（下次写入自愈）。
- **运动中一律拒写**（返回 `TASK_STORE_E_BUSY`）。

### 验证判据

- 上电 RTT 打印 8 行 `task slot i: name/len/crc/flags`（`main_app.c:194-205`）。
- 用上位机烧一个任务 → `TaskStore_Present(slot)=1`、`TaskStore_Load(slot)=0`、
  `TaskStore_Block(slot)` 必须是 **29 或 30**（是 27/28 就说明页分配算错了，会擦掉固件本体）。
- 烧完断电重启：任务还在，且**不会自动跑**（上电只扫不启动）。

## 11. 阶段⑨ 上位机联调

### 11.1 独立上位机怎么用

```
portable/host/
├── 启动上位机.bat          ← 真车：自动找串口，默认 921600
├── 启动上位机-仿真.bat      ← 无车调试界面（内置仿真信号源）
├── 启动上位机-列串口.bat    ← 只看车在哪个 COM
├── launch.ps1              逻辑都在这（-Baud / -HttpPort / -Sim / -ListPorts / -NoBrowser）
├── bridge/                 Python 桥（只依赖标准库 + pyserial）
└── web/dist/               已构建好的前端，桥直接托管
```

- 依赖 **Python 3.11+ + pyserial**；启动后浏览器开 **http://127.0.0.1:8770/**（只监听本机）。
- 手工方式：`cd portable/host && python -m bridge.main --serial COMxx --baud 921600`
  （`--port` 是 **HTTP 端口**，不是串口）。
- **串口安全闸**（`bridge/serial_safety.py`）：旧探针 `1366:0105`（J-Link V9）在
  **≥460800** 会崩进 bootloader，只能拔插 USB 救；新探针 `1366:1024` 可到 3Mbaud。
  闸门按 VID:PID 限制档位，要越过必须显式 `--force-baud`。
- 自测：`cd portable/host && python -m pytest -q tests`（本包实测 **148 passed, 8 skipped**；
  skip 的是需要本机 gcc 编真固件的对拍项）。

### 11.2 参数表 58 项必须同序同值

固件 `App/Svc/host_link.c` 的 `SPECS[]`（58 项）与上位机 `bridge/params.py` 的 `_SPECS`
**顺序、id、默认值**逐项一致。`HELLO` 里的 `param_crc` 就是把每项 `(id, def)` 打包算 CRC，
任一边漂移 → 上位机报"参数表不匹配"。
⚠️ 独立包里**删掉了**做这个对拍的测试（`test_params_spec.py` 等 6 个，见第 12 节），
所以换了板子/改过参数表之后，要么把那个测试从 `project/tools/console/tests/` 带过去，
要么人工逐项比对。

### 11.3 联调验证顺序（**别跳步**）

| 步 | 做什么 | 通过判据 |
|---|---|---|
| 1 | 只烧固件，不上上位机 | RTT 有 `host link init OK`，`HOST: tx` 每秒 +≈200 |
| 2 | 打开上位机、选串口模式 | 握手成功，显示固件版本/协议 v2/遥测 200Hz |
| 3 | 看参数是否一致 | 无"参数表不匹配"；参数页"从车读取"全成功 |
| 4 | 改一个安全参数（如循迹 Kp）→ 回读 | 回读值变化，RTT `sets=` +1；断电重启后仍在（NVRAM） |
| 5 | 看遥测波形 | yaw/电压/电流/编码器速度在动；`v_l/v_r` 不恒 0 |
| 6 | 驾驶模式（WHEELS）给一个低速 | 两轮同向、能停；松开发帧 500ms 后自动停（看门狗） |

| 8 | 跑完整任务 | 任务页显示状态号推进；`TaskRun_Tick` 不停在 WAIT；按停止能停 |

## 12. 裁剪：不移植的部分怎么处理

### 12.1 移植包里没有的东西

见 `firmware/README.md` 第 4 节：**Makefile、`main.c`/`main_app.c`、`stm32g4xx_it.c`、
`syscalls.c`、`hal_conf.h`、HAL/CMSIS/启动文件、自检固件那套**都不在包里
（它们是"这块板 + 这套工具链"的产物，不属于可移植层）。

### 12.2 构建变体怎么裁剪

`project/firmware/Makefile` 的一整套变体是**调试工具**，不是产品形态，按需保留：

| 变体 | 产物 | 内容 | 换板时 |
|---|---|---|---|
| `make` | `build-app/haixin-app.bin` | 主程序（UI + 通信 + 控制 + 任务） | **保留** |
| `make SELFTEST=1` | `build/haixin-selftest.*` | 上电自检：时钟/I2C/INA226/USART3 自环/按键计数 | 建议保留（新板第一次点亮就靠它） |
| `make SELFTEST=1 RESCUE=1` | `build-rescue/` | 救援固件：只跑时钟 + RTT，不碰外设（PA15/调试口出问题时用） | 建议保留 |
| `make SELFTEST=1 PA15TEST=N` | `build-pa15/` | PA15（I2C SCL）判决实验，N 取 2/3/4 | 一般可删 |
| `make SELFTEST=1 LOOPBACK=1` | `build-loop/` | USART3 自发自收一帧假 JY61P 数据 | 建议保留（验串口最省事） |
| `make DIAG=1` | `build-diag/` | `-DAPP_OLED_DIAG`：屏刷四组合轮播诊断 | 换屏/换总线时**必用** |
| `make MOTOR_BENCH=1` | `build-bench/` | `-DMOTOR_BENCH`：电机+编码器台架自测（结果走 RTT） | 换电机时**必用** |

裁剪原则：
- 删 `App/Src/oled_diag.c` 与 `App/Bsp/motor_bench.c` 之前先确认没定义对应宏
  （两个文件平时是空的，不占 Flash，留着更省事）。
- 自检固件依赖 `Core/Src/selftest.c`、`ssd1315.c`、`pa15test.c`、`probe_jy61p.c`
  （不在移植包内，需要就从 `project/firmware/Core/Src/` 拷）。
- 想省 Flash：去掉 `-g3` 不影响镜像（只影响调试信息），`-Og→-Os` 能省 ~12KB；
  `-flto` 还能再省 ~9KB，但要先验证 `__weak` 钩子与 RTT 符号不被吞（项目里尚未启用）。

### 12.3 功能级裁剪

| 想省掉 | 怎么改 | 影响 |
|---|---|---|
| 显示 | 不调 `app_ui_*`/`KK_UI_*`，`OLED_*` 全删 | 没有菜单/按键反馈，但控制、通信、任务照常 |
| 上位机链路 | 不调 `host_link_*`，`board_dl_*` 不初始化 | 参数只能靠改默认值 + 重编；NVRAM 仍可用 |
| 任务编排 | 不调 `TaskRun_Tick`、不调 `TaskStore_*` | 少 8KB Flash；控制环与驾驶仍可用 |
| 灰度/循迹 | `MOTION_GYRO` 单角度环 | 只能做转向/直行，不能巡线 |
| 电源监测 | 不调 `ina226_*` | 低压保护失效，**别上车跑** |

## 13. 常见移植坑

按"踩了会浪费一天"排序，全部有代码/文档出处。

1. **G4 的 DMAMUX1 时钟必须显式开** —— `__HAL_RCC_DMAMUX1_CLK_ENABLE()`
   （`board.c:330-334`）。漏了：异步传输**永不发生**，但阻塞式的 `OLED_Init()` 照常成功，
   屏一直黑而日志一切正常。判定：测 `OLED_IsBusy()` 时长对不上理论值（见 10.3）。
2. **400kHz + DMA 刷屏偶发黑屏** —— 两轮人眼实验：同一配置两次结果不同（临界偶发），
   根因是 HAL"中断发页命令 → DMA 发页数据"的交接竞争。当前 `kk_ui_config.h` 默认
   `KK_UI_REFRESH_DMA`，所以**不传 `-D` 就是 DMA**；建议显式切 IT。
   回退顺序：IT → 阻塞 → 100kHz 阻塞。
3. **UCPD 死电池下拉** —— 复位后 `PWR_CR3.UCPD_DBDIS=0`，PB4/PB6（UCPD1_CC1/CC2）挂
   5.1k 下拉，而这两个脚正好是**两路编码器的 A 相**；舵机 PA9/PA10 一摆就触发。
   10k 上拉 5V 分压 ≈1.69V，落在 VIL/VIH 之间的未定义区 → 计数被吞。
   修法：`HAL_PWREx_DisableUCPDDeadBattery()`（已写在 `board_clock_init()` 里，换板别丢）。
4. **Flash 单 bank 擦写停 CPU ~30ms**，且**擦除粒度是 4KB 块不是 2KB 页**。
   所有"运动中擦写"必须拒（`nvram_poll()`、`TaskStore_Commit()` 都有这道闸）；
   页分配必须按块算（见第 9 节）。搞错会擦掉固件本体 → HardFault。
5. **字模缺字静默不画** —— 不是乱码、不是方框，就是少一个字。只有
   `check_charset.mjs` 查得出来（10.3）。
6. **旧工程源码编码混杂**（GBK/UTF-8 都有），统一按 GBK 转会吞换行把结构体成员注释掉。
   必须逐文件自动识别：先严格 UTF-8，失败再 GBK。
7. **Makefile 是 GBK**，用 PowerShell 改要 `[Text.Encoding]::GetEncoding(936)` 读写，
   否则中文注释被破坏；`.bat` 必须是 **CRLF + 纯 ASCII**（cmd 用 OEM 代码页读脚本）。
8. **PA15 与 SWCLK 相邻**（LQFP64 第 51/50 脚）：PA15 配成 I2C SCL 后一旦与 SWCLK 连锡，
   调试口直接`Failed to initialize DAP`。排查顺序：断电量两脚通断 → 按住复位连 →
   烧 `make SELFTEST=1 RESCUE=1` 救援固件。
9. **蜂鸣器"一直响"** —— 旧实现只在主循环里关，主循环一卡就永久响。
   必须有 5ms 中断里的 `board_buzzer_safety()` 保险丝（150ms 强制掐）。
10. **按键"五键同时按下"** —— `last_keys` 若初始化成 `0xFF`，循环第一次读到空闲 `0x00`
    会被算成"五个键刚按下"。正确做法：进循环前先读一次。
11. **编码器符号**：左右电机镜像安装，**只翻右路**。曾把两路都翻（以为都反了），
    结果右路反馈变正反馈 → 右路输出乱摆、编码器读数乱跳、速度完全不受控。
    判据：两轮都朝前进方向推，两路计数**都为正**。
12. **TIM6 中断优先级**：提到 0 实测原地转失控（峰值 300°、末值随机），
    保持 **6**（与外设中断同组）。要改只建议提到 4。
13. **OLED 上电时序**：冷启动不亮、多按几次复位才亮。修法是"上电等 150ms + 失败就
    总线恢复 + 最多 10 次重试 + 第 2 次起降到 100kHz"（`main_app.c:138-166`）。
    这同时说明：**别为屏幕牺牲总线速率**，循迹/灰度比屏重要。
14. **KK_UI 自定义页没有内置返回** —— 不在 `KK_UI_CustomOnInput()` 里
    `KK_UI_CustomRequestClose()`，进去就出不来（历史症状：卡在某页只能改屏上一个数字）。
15. **串口安全闸**：旧 J-Link V9（`1366:0105`）在 ≥460800 会崩进 bootloader，
    只能物理拔插救回。换探针前先看 `bridge/serial_safety.py` 的分档表。
16. **参数表漂移**：`SPECS[]` 与上位机 `params.py` 顺序/值不一致 → 握手报"参数表不匹配"，
    但车看起来还能跑，很容易被忽略。加参数时两边 + `docs/上位机通信协议.md` 一起改。
17. **NVRAM 记录长度必须 8 字节对齐**：按双字写，除不尽则尾部字段永远写不进去
    （编译期断言 `nvram_record_size_must_be_8x` 会挡住）。
18. **烧录**：J-Link 脚本必须带 `device STM32G474RB`，否则 `loadbin` 报
    "Writing target memory failed"；G474 的 **DBANK 选项位必须是单 bank**（双 bank 时
    128KB 只覆盖前 64KB，超过 `0x08010000` 的镜像会**静默丢失**）。

## 15. 移植包现状：缺什么、需要谁拍板

**包里缺的**（详见 `firmware/README.md` 第 4 节）：
`Makefile`、`main.c`/`main_app.c`、`stm32g4xx_it.c`、`syscalls.c`、`hal_conf.h`、
HAL/CMSIS/启动文件、以及自检固件（`selftest.c`/`ssd1315.c`/`pa15test.c`/`probe_jy61p.c`）。
其中 **`main_app.c` 最要紧**：初始化顺序与主循环节拍全靠它，附录第 7 节给了完整顺序清单，
照抄即可。

**需要用户/维护者拍板的三件事**：

1. **屏刷方式**：`kk_ui_config.h` 默认 `DMA`，但历史决策与实测结论是"400kHz+IT 才稳"。
   当前项目里这条**尚未统一**（`make` 不传 `-D` ⇒ 实际编出 DMA）。移植时建议直接指定
   `-DKK_UI_REFRESH_MODE=KK_UI_REFRESH_IT` 并做 10 分钟 A/B。
2. **`pack_portable.py` 会删掉本手册与另两份说明所在目录**：`portable/firmware/`、
   `portable/docs/` 每次重跑都被 `rmtree` 重建，写在里面的 `firmware/README.md` 与
   `docs/移植与接口说明.md` 会丢。需要在脚本里加"生成/保留这两份文档"的逻辑，
   或约定"最后才跑打包脚本"。
3. **独立上位机删掉了 6 个与固件同仓的测试**（含校验 58 项参数同序同值的
   `test_params_spec.py`、校验默认值的 `test_firmware_defaults_sync.py`、
   校验任务字节的 `test_task_bytes.py`）。换板/改参数表后这两边只能人工对齐，
   建议把这几个测试脚本一起带走，或在新仓库里重建。

**本工程里已知的、与移植无关但会影响"跑起来像不像"的遗留项**（不要误当成移植问题）：
`SpeedControl` 满量程计数参数（`0x0308`）与 `counts_per_rev` 的标定口径、
`app_ui.c` 的 `g_cfg` 默认值与 `SPECS[]` 存在若干项不一致、故障处理不关电机且无 IWDG。
这些属于"这套参数还没定稿"，不是移植步骤的一部分。
